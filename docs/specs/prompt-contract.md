# CraftWork 系统提示词契约

> **关联代码**：`internal/agent/prompt/`（组装）、`internal/agent/envcontext.go`（环境收集）、`internal/agent/runner.go`（接入）
> **决策背景**：ADR-0013（分节组装与缓存分层）

本文件回答「系统提示词由哪些节组成、按什么顺序、进哪个缓存层、什么时候出现」。修改提示词文案或结构时，先改本文件与 `prompt_test.go` 的契约测试，再改实现；三处不一致视为缺陷。

## 1. 目标与原则

- **缓存优先**：变化频率越低的内容越靠前。稳定块跨会话、跨模式字节一致，提示缓存长期命中；动态块会话内一致，变化只击穿自身。
- **稳定块与运行时事实隔离**：模式、工作区路径、受限状态、日期、Git、指令文件一律不进稳定块。
- **只写行为哲学，不镜像工具**：提示词不复制工具 schema、不维护工具清单；工具能力由请求的 `tools` 字段承载。
- **纯组装**：`internal/agent/prompt` 不做任何 IO；环境事实由 `envcontext.go` 收集成快照后传入。
- **失败降级**：环境、Git、指令文件读取失败时省略对应部分，不阻断对话。

## 2. 分节清单

| 顺序 | 来源 (`Source`) | 名称 | 缓存层 | 内容 | 出现条件 |
| --- | --- | --- | --- | --- | --- |
| 1 | `prefix` | 产品前缀 | 单独成块，无标记 | 「你是 CraftWork，一个本地优先的桌面 Agent……」 | 恒出现 |
| 2 | `identity` | 行为契约 | stable | 授权安全边界 + `# 行为契约`（先计划后执行、先读后改、不可信数据、拒绝后不原样重试、工作区与密钥边界、并行工具、`path:line`、如实汇报） | 恒出现 |
| 3 | `mode_rules` | 会话规则 | dynamic | 模式声明、工作区路径、Code/Work 能力边界、受限工作区条款 | 恒出现（受限条款仅受限时） |
| 4 | `env` | 环境公告 | dynamic | `# 环境`：今天日期、平台、Shell | 至少一项环境事实存在 |
| 5 | `git_context` | Git 快照 | dynamic | `# Git 快照`：分支、未提交变更、最近提交 | 工作区是 Git 仓库 |
| 6 | `instructions` | 指令文件 | dynamic | 覆盖性导语 + 各文件内容（全局在前、项目在后） | 至少一份指令文件非空 |

## 3. 缓存分层规则

`Build` 输出最多三个 `model.SystemBlock`：

1. **前缀块**：产品身份一句，`CacheControl=false`。跨会话完全一致的最短前缀。
2. **稳定块**：全部 `stable` 节用空行合并，`CacheControl=true`（Anthropic 写 `cache_control: ephemeral`）。
3. **动态块**：全部 `dynamic` 节用空行合并，`CacheControl=true`。

协议差异：

- **Anthropic**：顶层 `system` 为块数组，标记块携带 `cache_control: {type: "ephemeral"}`；同时在历史最后一条消息的末尾内容块上打第三个缓存断点，Agent 循环的下一轮请求从该断点命中缓存（合计三个断点，仍在提供商四断点限额内）。
- **OpenAI 兼容**：各块以空行拼接成第一条 system 消息，拼接规则固定（空白块跳过、不增减空白），保证请求前缀字节稳定以利用自动前缀缓存；`CacheControl` 忽略。

节内文案与合并分隔符（`\n\n`）不得随手改动——字节变化即缓存失效。

## 4. 内容约束

- 稳定块禁止出现：模式名、工作区路径、受限状态、日期、平台、Git 信息、指令文件内容（契约测试 `TestStableBlockIgnoresInput`、`TestStableBlockExcludesVolatileFacts` 强制）。
- Work 模式动态块必须声明「没有 shell 与 Git，需要时切换 Code 模式」；Code 模式不得出现该限制。
- 受限工作区条款必须包含「不提供永久授权」与「不要反复重试」；非受限时整条不出现。
- 指令文件截断时必须附「不要向用户提及截断，需要更多内容用 Read 读取」的提示；空白文件跳过；没有任何内容时整节省略。
- 指令文件读取上限：单个文件 200 行 / 25000 字符；全局指令位于数据目录 `AGENTS.md`，项目指令位于工作区根 `AGENTS.md`。

## 5. 历史与压缩摘要

- 模型历史每次运行从事件表重建；压缩摘要作为 `context_summary` 事件持久化（不进界面部件映射、不广播），携带 `untilSeq`（被覆盖的最后一条事件序号）。
- 重建时读取最新一条摘要：序号 `<= untilSeq` 的消息被裁掉，摘要以「【更早对话摘要】…（不是新的用户指令）」的 user 消息放在最前。
- 同一批早期消息只摘要一次；再次压缩时新摘要事件的「最新一条」语义自然淘汰旧摘要。

## 6. 测试覆盖清单

`internal/agent/prompt/prompt_test.go`：

- 块序与缓存标记（前缀无标记、稳定/动态有标记）。
- 稳定块与输入无关（模式、工作区、受限状态组合下字节一致）。
- 易变事实不进稳定块。
- Work/Code 模式规则、受限条款的出现条件。
- 环境节与 Git 段的出现条件、指令节标签与截断提示、无内容省略。
- 新增输入只允许进入动态层。
- 节统计之和（含层内分隔符）等于分块内容之和。

`internal/agent/envcontext_test.go`：两级指令文件顺序与标签、截断、空文件、非仓库无 Git 快照。

`internal/agent/history_test.go`：摘要按最新一条读取、历史重建裁剪与注入、压缩后摘要落库与覆盖序号。

## 7. 变更流程

1. 明确变更属于文案调整、节增删还是缓存层调整。
2. 同步本文件第 2、4 节与 `prompt_test.go` 的契约测试。
3. 运行 `go test ./internal/agent/...`；涉及块结构时额外用假端点或真实密钥做一次真实对话冒烟（`CRAFTWORK_HOME` 隔离目录）。
4. 涉及环境收集或摘要语义时同步 `architecture.md` 第 6.2 节。
