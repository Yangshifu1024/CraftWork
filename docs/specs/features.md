# CraftWork 功能规格

本文件是功能的验收基准：每条功能有编号（`F-模块-序号`）、优先级与验收要点。

- **P0** 为 v1 必须交付；**P1** 为 v1 应交付（可在 v1.1 补齐）；**P2** 为后续版本候选。
- 「必须」「不得」为强制要求；「应该」「建议」为推荐做法。
- 风险分级与审批档位的完整规则见 `docs/adr/0003`；机制落地见 `architecture.md`。

### 密钥文件规则

- 路径固定为 `~/.craftwork/keys.json`；`~/.craftwork` 目录权限 0700，文件权限 0600；Windows 使用仅当前用户可读写的访问控制。
- 文件格式为 `{"version":1,"providers":{"<provider-id>":"<api-key>"},"mcp":{"<server-id>":"<secret|tokens>"}}`。
- 同一提供商下的多个模型共用同一密钥；不同密钥必须配置为不同提供商。
- 用户从模型目录导入时沿用 models.dev 的提供商标识（如 `openai`、`anthropic`、`openrouter`），手动添加时使用自定义标识（如 `kimi`、`vllm`）。
- MCP 服务器的密钥、OAuth 令牌与刷新令牌放在 `mcp` 节点，按服务器标识保存，不与模型或会话绑定。
- 文件只由应用读写；不纳入版本控制，不导出，不写入日志，不进入对话上下文与工具输出。
- 启动时检查文件权限；若宽于 0600，拒绝读取并提示用户修复，不静默降级。
- 环境变量可作为兜底，优先级低于密钥文件；迁移到文件后提示用户删除环境变量。
- 备份与导出必须排除 `keys.json`。
- 风险说明：以文件权限与磁盘加密为边界，安全性低于操作系统专用凭据存储（取舍见 ADR-0005）；建议开启全盘加密并以最小权限运行。

### 工具规则

- Code 模式提供上述全部工具；Work 模式只提供服务商、文件、文档、MCP 工具，不提供 Shell、Git、终端。
- 风险等级按参数提升：访问工作区外路径或联网提升到 R3；破坏性命令提升到 R4。
- 工具输出默认上限 32 KB（`Registry.Execute` 出口统一截断），超出部分写入本地大输出文件；二进制输出只返回类型、大小与校验值。
- 去除 ANSI 与控制字符；超长行折行或截断；错误返回结构化错误码与可读信息。
- 只读工具可并行，默认上限 8；写工具按工作区串行；同一文件使用文件锁。
- 单次 run 的模型调用往返上限可配置（默认 300，0 表示不限制）；工具调用次数与 Token 用量上限可配置。
- 子 Agent 默认只读；需要写时提升权限并走审批；子 Agent 不自主创建新的子 Agent。
- 任务清单状态由工具写入，不由模型口头声称；`ask_user` 阻塞当前 run，不得自动选择默认答案。
- `git_commit` 默认不推送；推送属于 R3，必须审批。

### 文档规则

- 文档写入属于 R1，必须每次审批；审批内容包含文件路径、变更摘要与文本级差异。
- 写入前备份原文件；备份保留在本地，可由用户恢复。
- Word 与 Excel 的编辑为文本级：修改内容，不重建排版；不保证复杂样式、图片、图表、页眉页脚的完整保真（ADR-0010）。
- Excel 不计算公式，只读写值与公式字符串。
- PDF 只读；PDF 编辑、表单填写、页面合并与拆分不在 v1。
- 文档解析在后台执行；大文档不阻塞聊天与界面。
- 文档内容视为不可信数据；模型不得执行文档中的指令或宏。

### 办公集成规则

- 邮件与日历通过 MCP 接入，推荐模板只预置服务器地址、命令、权限说明与授权方式，不预置任何账号或密钥。
- 用户必须显式授权；OAuth 令牌与刷新令牌存放在 `~/.craftwork/keys.json` 的 `mcp` 节点。
- 邮件与日历只读；应用内草稿由模型生成，用户复制到邮件客户端或日历应用后自行发送与创建（ADR-0011）。
- 邮件与日历内容只发送给用户选择的模型；不写入日志、不导出、不用于遥测。

## 7. 审批与安全

风险五级（R0–R4）定义、四档审批档位（分级 / 严格 / 只读 / 自由）与自由档位的确认约束见 `docs/adr/0003`，此处不重复维护。

| 编号 | 优先级 | 功能 | 验收要点 |
| --- | --- | --- | --- |

### 审批规则

- 审批不自动超时；用户取消 run 或关闭会话视为拒绝。
- 审批弹窗展示原始命令、路径或文档差异，不展示模型生成的自然语言解释作为唯一依据。
- 弹窗默认焦点在「拒绝」，不得默认选中「允许」；多个审批排队展示。
- 沙箱是纵深防御，审批、路径校验、命令解析、审计必须同时存在。
- 提示注入防护不追求识别所有恶意文本，而是保证高风险操作一定经过审批与审计。
