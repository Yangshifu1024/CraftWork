## 二、定下来的决策（后续不要回退）

1. **运行环境不进任何全局可变状态**。策略引擎只持有审批档位（真实全局设置）；`Engine.Action/AllowsPermanent` 显式接收 `restricted` 参数。不要再给 Engine/Registry 加回 workspace 字段。
2. **run 行与会话状态的写入序列归 Runner 所有**。服务层不要自己拼 `CreateRun + SetThreadStatus`。
3. **保存/应用差异必须显式携带工作区身份**（`FileContent.workspaceId` / `diff.workspaceId`），不要再读 `workspaceID()` 环境帮助函数。
4. **发送策略只允许一个入口**（`threads.submit`）；新增发送路径（快捷指令、浮层等）接它，不要绕过策略。
5. **Mock 不复刻行为规则**（标题提取、空校验已删）。端口类型维持由 `desktopApi` 推导的既定决策（`81531bb`），不要改成手写第二份接口签名——它解决不了 mock 的行为漂移。
6. **部件/载荷形状有类型/single-table 的家**：Go 侧 `agent.ToolCallPart`，前端 `partRegistry.tsx`。新增部件走「Go 事件 + reducer handler + 注册表」三处，不要再造平行分类表。

## 三、遗留与后续机会（按价值排序）

1. **grants「本会话」键不含 threadID**（`internal/agent/grants.go:29`）：`session` 授权实际是进程级，非受限的不同工作区之间命令前缀授权互串。建议键纳入 scope 上下文。
2. **备份管道双轨**（`internal/service/workspace.go` 的 `backup` 与 `internal/tools/tools.go` 的 `Registry.backup` 做同一件事）：可合一为「写入前备份」模块，编辑器与工具共用出口。
3. **`Recorder.Flush` 的调用义务落在 runner 三个收尾函数**：「结束必须 Flush」是接口上的隐式顺序约束，可挪进 Recorder 自身。
4. **审批没有超时机制**：只受 ctx 取消约束；`modelRequestTimeout` 只管模型流。是未实现行为，不是未测行为。
5. **`simulateRun` 仍是协议行为的第二份实现**（mock.ts，约 170 行）：要彻底消除需要「录制 Go 行为 → mock 回放」的工具链，是一个独立小项目。
6. **runner 测试 harness 双份**（runner_test 与 chat_test 各装配一遍 agent 栈）：可抽共享装配模块。
