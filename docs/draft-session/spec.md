## Problem Statement

用户点「新建对话」后，一条没有任何消息的空会话立即写入侧栏：点几次就残留几个「新对话」，侧栏与搜索被空会话污染，重启应用后还会停在这些空会话上。用户的本意只是「先打开输入框想一想」，并不想产生任何记录。

## Solution

新建对话变为纯界面草稿态：不写库、不出现在侧栏、重启不产生脏数据。每个归属（临时会话、每个项目）各自保留一个草稿槽，未发送文本、附件与模型选择随槽保存，切走再切回互不覆盖。用户发出首条消息的那一刻才真正创建会话——标题取自首条消息的短标题，会话立即落入对应分组。历史遗留的空会话做一次性清理。

对齐参考（ZCode）：新建即草稿、首条消息发送时才沿发送路径落库；本应用因单活动会话形态，不需要 deferred 会话标记与列表过滤闸门。

## User Stories

1. 作为用户，我希望点「新建对话」后侧栏不出现任何新条目，以便侧栏只显示真正有内容的会话。
2. 作为用户，我希望在草稿态输入的文字与附件在切到其他会话再切回后原样保留，以便慢慢补充想法而不怕丢失。
3. 作为用户，我希望临时会话有一个专属草稿槽，以便随时回到未发送的想法。
4. 作为用户，我希望每个项目各自有一个草稿槽，以便在不同项目间切换时各自的未发送内容互不覆盖。
5. 作为用户，我希望重启应用后草稿文本与附件仍在，以便意外关闭也不丢内容。
6. 作为用户，我希望在草稿态就能选择模型，发送后新会话直接使用该模型，以便不必创建后再改。
7. 作为用户，我希望草稿态的界面标题显示归属（「新对话」或项目名），以便发送前就知道消息会落到哪个分组。
8. 作为用户，我希望发出首条消息后会话立即出现在对应分组，并使用首条消息的短标题，以便一眼认出会话。
9. 作为用户，我希望未配置模型时发送被明确引导报错，且不留下任何会话痕迹，以便配置好模型后原样重试。
10. 作为用户，我希望发送失败时草稿文本与附件完整还原，以便直接重发而不是重新打字。
11. 作为用户，我希望在每个项目的分组上直接新建该项目的会话，以便不必先开临时会话再换工作区。
12. 作为用户，我希望升级后历史遗留的空「新对话」被自动清理，以便侧栏与搜索结果干净可信。
13. 作为用户，我希望删除项目时该项目草稿槽一并清除，以便不残留死数据。
14. 作为用户，我希望搜索与命令面板永远搜不到空会话，以便结果可信。
15. 作为用户，我希望草稿态下附件、模式切换等输入区能力照常可用，以便草稿与正式会话体验一致。
16. 作为用户，我希望重复点「新建对话」/ ⌘N / ⌘K 永远回到同一个草稿，以便心智模型简单——新建不产生第二条草稿。
17. 作为用户，我希望其他会话在后台运行时新建草稿不受影响，以便并行任务与开新会话互不干扰。
18. 作为用户，我希望草稿态按 Enter 后创建与发送一气呵成，以便与普通发送的手感无差别。

## Implementation Decisions

- 草稿是渲染层状态，不落库：草稿态定义为「当前活动会话为空」；主进程不感知草稿，列表查询天然看不到草稿，无需任何过滤闸门。
- 草稿按归属分槽：每个工作区（含内置临时目录的 conversation 工作区）各自一个槽；槽内容为文本、附件路径与模型引用；持久化在渲染层本地存储，按模式 + 工作区分 key。
- 首发原子路径：对话服务新增「创建并首发」方法，一次调用完成模型校验 → 创建 Thread（标题 = 首条消息短标题，取不到回落「新对话」且自动命名标记置位）→ 经 Recorder 写用户消息事件 → 启动 Run，返回 threadId 与 runId。
- 模型校验前置：模型未配置或不可用时在创建 Thread 之前抛错，保证零落库；错误文案与既有发送路径一致。
- 既有普通发送语义不变（仅服务已存在会话的路径）；运行中引导、取消、审批不受影响。
- 通道表新增「创建并首发」方法，preload 桥与 IPC 接线三处同步；线程创建通道保留但渲染层不再直接调用，由首发路径内部复用创建逻辑。
- 空会话一次性清理：追加数据库迁移版本，删除「无任何事件且自动命名且标题为『新对话』」的线程；有事件或被手动改名的会话一律保留。
- 短标题逻辑复用现有自动命名模块的短标题函数；LLM 自动命名链路完全复用不改动。
- 侧栏项目分组新增「在该项目下新建会话」入口，点击进入该项目草稿槽；新建项目流程收尾同样进入项目草稿槽。
- 草稿态顶部标题显示当前槽归属（临时显示「新对话」，项目槽显示项目名）。
- 删除工作区时同步清理其草稿槽；启动时恢复草稿文本但不自动进入草稿态（有会话则选中最近会话，无会话则自然落在临时草稿态）。
- 依赖既有「临时会话默认工作区」改动（conversation 工作区解析）作为前置。

## Testing Decisions

- 好的测试只验证外部行为：数据库落库结果、服务返回值与抛错，不窥探内部调用细节。
- Seam 1（新增，最高可测点）：对话服务「创建并首发」——真实 SQLite 临时目录 + 桩 Runner。覆盖三态：成功时线程落库（短标题、用户消息事件存在、Run 启动）；模型未配置时抛错且线程零落库；工作区不存在时抛错且零落库。
- Seam 2（既有 store seam）：空会话清理迁移——空自动命名会话被删；有事件的会话、手动命名的会话不误删；迁移版本递增且可重开。
- 短标题取词复用自动命名模块的既有测试覆盖，不新增。
- 渲染层草稿槽不写单测（仓库无渲染层测试先例），按验证清单做隔离目录冒烟走查：空侧栏新建不出现条目 → 草稿输入切走切回不丢 → 两项目草稿互不覆盖 → 未配模型首发零痕迹 → 首发后落入正确分组与短标题 → 重启草稿仍在且无空会话。
- 先例：store 层测试的临时目录建库模式与迁移断言写法。

## Out of Scope

- 多面板 / 分屏同时展示多个会话（不引入 ZCode 的预热 deferred 会话与 single-flight 协调器）。
- LLM 自动命名链路的改动（完全复用现状）。
- 「带标题预创建会话」的独立入口。
- 草稿的跨设备同步与历史版本。
- 渲染层草稿槽的单元测试。
