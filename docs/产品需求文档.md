## 1. 产品定位与范围

### 1.1 一句话定位

CraftWork 是一个完全本地运行、以 Go 为内核、用 Wails3 承载 React 界面的桌面 Agent。它提供 **Code** 与 **Work** 两种模式：Code 模式帮助开发者在真实代码工作区里读代码、改代码、跑命令、看差异；Work 模式帮助日常办公人员读取文档、编辑 Word 与 Excel、汇总邮件与日历、生成草稿。所有高风险操作都经过审批并留下审计记录。

技术栈不是产品卖点。对外差异点只有三条：**Go 内核与全部系统能力在本地执行、数据不出本机、所有高风险操作可审计可回滚**。

### 1.2 两种模式

| 维度 | Code 模式 | Work 模式 |
| --- | --- | --- |
| 主要用户 | 开发者、技术负责人、平台运维 | 日常办公人员、需要处理文档的开发者 |
| 默认工作区 | 代码仓库 | 普通文件夹或文档目录 |
| 核心能力 | 代码编辑、Shell、Git、差异、终端、MCP | 文档读写、PDF 阅读、邮件与日历只读、草稿、文件预览 |
| 界面 | 三栏：工作区与会话、聊天、差异/文件/终端 | 三栏：会话与文件树、聊天、文档预览 |
| 隐藏能力 | 无 | Git、差异面板、终端、Shell 工具 |
| 线程列表 | 仅 Code 线程 | 仅 Work 线程 |

模式是工作台级切换：切换模式只改变界面、可用工具和线程列表，不改变工作区本身。同一个文件夹可以在两种模式下打开。

### 1.3 目标用户

- **独立开发者与小团队工程师（首要）**：快速理解陌生代码、修缺陷、写测试，少切换工具。
- **日常办公人员（次要）**：整理文档、总结 PDF、修改 Word 与 Excel、汇总邮件、准备日程草稿。
- **技术负责人与架构师（次要）**：关注审批可见、操作可追溯、用量可统计、密钥只存在本地受保护文件。
- **平台与运维工程师（次要）**：需要好用的终端，并通过 MCP 连接内部系统与数据库。

### 1.4 v1 范围

| 模块 | Code 模式 | Work 模式 | v1 不包含 |
| --- | --- | --- | --- |
| 模式 | Code/Work 切换、线程隔离、工作区共享 | 同左 | 同一线程内切换模式 |
| 对话 | 流式文本、Markdown、代码块、图片、附件、停止、重新生成 | 同左 | 语音、视频 |
| 模型 | 多提供商、连接测试、用量统计、失败转移 | 同左 | 模型微调、自动路由学习 |
| 代码工具 | 文件读写、Glob、Grep、Shell、Git 状态与差异、补丁、任务清单、子 Agent、向用户提问 | 不提供 Shell、Git、终端 | 浏览器自动化、Computer Use |
| 文档 | 文本文件编辑 | Word 与 Excel 文本级读写、PDF 只读、文本级差异预览 | PDF 编辑、Office 完整排版编辑、新建 Word/Excel、旧版 `.doc` 与 `.xls` |
| 办公集成 | 通过 MCP 使用 | 邮件与日历只读、应用内草稿、内置推荐 MCP 模板、系统浏览器打开链接 | 发邮件、创建或修改日程、服务端草稿、网页内容读取 |
| 审批 | 风险分级、单次/会话/工作区授权、审计 | 同左，文档写入每次审批并备份 | 企业级角色权限 |
| 编辑器 | 语法高亮、行号、搜索替换、差异面板、应用或拒绝补丁 | 文档预览与文本级差异 | 完整语言服务器协议客户端、多光标、代码折叠 |
| 终端 | 多标签、伪终端、真彩色、中文宽字符、搜索、复制粘贴 | 不提供 | 终端分屏、SSH 管理器 |
| MCP | 标准输入输出、Streamable HTTP、工具发现、启停、重连、按服务器授权 | 同左，包含推荐邮件与日历模板 | MCP 市场、自动安装 |
| 桌面 | 主题、快捷键、命令面板、通知、拖放、自动更新 | 同左 | 托盘、全局热键、开机启动 |
| 数据 | 本地数据库、审计、用量、备份、导出、更新 | 同左，包含文档备份 | 云同步 |

**硬约束**：Go 承担内核与全部系统能力，界面使用 Wails3 + React + TypeScript 并运行在系统 WebView 中；**不加载任意第三方网页**；本地优先；可审计、可撤销；优先复用成熟组件。

### 1.5 核心场景

**Code 模式**

1. **接手陌生仓库**：询问项目结构与测试方式，Agent 读文件、跑测试并给出带文件引用的回答。
2. **修复缺陷并验证**：Agent 读代码、改文件、跑测试，最后展示差异，用户逐块决定应用或拒绝。
3. **实现小需求并提交**：Agent 用任务清单拆解步骤，修改多个文件，运行构建与测试，提交前审批。

**Work 模式**

4. **阅读与总结文档**：打开 PDF 或 Word，要求总结要点、提取表格、列出待办。
5. **修改 Word 或 Excel**：要求调整段落、修改表格文字、更新单元格值与公式；写入前审批并展示文本级差异。
6. **汇总邮件与准备日程**：读取邮件与日历，生成回复草稿和日程安排草稿；不自动发送、不自动创建。
7. **整理文件夹**：读取本地文件，生成清单、重命名建议、归档方案，用户确认后执行。

### 1.6 约束

- 技术栈：Go 作为后端与系统能力的主力语言；Wails3 提供桌面外壳、窗口与系统 WebView；React + TypeScript 负责界面。不使用 Electron、Tauri 或任何自带 Chromium 运行时的方案。
- 不加载任意第三方网页：界面资源只来自本地内嵌包；外部链接只通过系统浏览器打开。
- 不执行不可信 HTML 与脚本：Markdown 中的原始 HTML 按文本处理；前端资源响应带严格 CSP；密钥不进入前端。
- 本地优先：会话、密钥、文件、日志默认保存在本机；不向外部上传代码或文档。
- 可审计、可撤销：工具调用、审批、文件修改都有记录；危险操作可拒绝、可回滚。
- 开源：Apache-2.0 许可证，贡献流程使用 DCO。

**密钥文件规则**：

- 路径固定为 `~/.craftwork/keys.json`；`~/.craftwork` 目录权限 0700，文件权限 0600；Windows 使用仅当前用户可读写的访问控制。
- 密钥按提供商保存，文件格式为 `{"version":1,"providers":{"<provider-id>":"<api-key>"},"mcp":{"<server-id>":"<secret>"}}`。
- 同一提供商下的多个模型共用同一密钥；不同密钥必须配置为不同提供商。
- 应用不内置任何提供商。用户从模型目录导入时沿用 models.dev 的提供商标识（例如 `openai`、`anthropic`、`openrouter`），手动添加时使用自定义标识（例如 `kimi`、`vllm`）；同一标识下的模型共用一个密钥。
- 迁移策略：升级后不自动恢复旧的内置提供商；用户需要重新添加提供商并选择模型。旧线程中的模型若已不可用，界面提示“模型不可用”。
- MCP 服务器的密钥、OAuth 令牌与刷新令牌放在 `mcp` 节点，按服务器标识保存，不与模型或线程绑定。
- 文件只由应用读写；不纳入版本控制，不导出，不写入日志，不进入对话上下文与工具输出。
- 启动时检查文件权限；若宽于 0600，拒绝读取并提示用户修复，不静默降级。
- 环境变量可作为兜底，优先级低于密钥文件；迁移到文件后提示用户删除环境变量。
- 备份与导出必须排除 `keys.json`。
- 风险说明：该方案以文件权限与磁盘加密为边界，安全性低于操作系统提供的专用凭据存储；同一用户下的恶意进程仍可能读取，建议开启全盘加密并以最小权限运行。

**工具规则**：

- Code 模式提供上述全部工具；Work 模式只提供服务商、文件、文档、MCP 工具，不提供 Shell、Git、终端。
- 风险等级按参数提升：访问工作区外路径或联网提升到 R3；破坏性命令提升到 R4。
- 工具输出默认上限 32 KB，超出部分写入本地大输出文件；二进制输出只返回类型、大小与校验值。
- 去除 ANSI 与控制字符；超长行折行或截断；错误返回结构化错误码与可读信息。
- 只读工具可并行，默认上限 8；写工具按工作区串行；同一文件使用文件锁。
- 单次 run 的模型调用上限默认 200；工具调用次数上限默认 100（建议值）；Token 用量上限可配置。
- 子 Agent 默认只读；需要写时提升权限并走审批；子 Agent 不自主创建新的子 Agent。
- 任务清单状态由工具写入，不由模型口头声称；`ask_user` 阻塞当前 run，不得自动选择默认答案。
- `git_commit` 默认不推送；推送属于 R3，必须审批。

### 2.7 审批与安全

## 3. 非功能与质量要求

### 3.1 性能

| 指标 | 目标 | 测量方式 |
| --- | --- | --- |
| 冷启动到可交互 | < 2.5 秒 | 分三段记录：Go 进程启动、WebView 就绪、前端首帧可输入 |
| 热启动 | < 1.0 秒 | 已有进程或缓存 |
| 首 Token 延迟 | P50 < 1.5 秒 | 点击发送到首个增量；模型网络时延单独统计 |
| 流式渲染 | 60 fps | 长 Markdown 滚动；统计 WebView 掉帧 |
| 输入延迟 | < 50 毫秒 | 按键到 DOM 更新（系统 WebView 口径） |
| 空闲内存 | < 400 MB | 单窗口、空线程；系统 WebView 常驻基线，M0 实测后定稿 |
| 首屏脚本体积 | < 600 KB gzip | 主包与首屏依赖；编辑器、终端、设置按需加载 |
| 10 万条消息线程 | < 800 MB | 分页加载与虚拟列表 |
| 10 MB 文本文件打开 | < 1 秒 | CodeMirror 只读预览，可视区域渲染 |
| 50 MB Word/Excel 打开 | < 3 秒（建议值） | Go 侧后台解析；不阻塞界面 |
| 数据库查询 | < 20 毫秒 | 线程列表、全文搜索 |
| 文件树首屏 | < 500 毫秒 | 1 万个文件，忽略依赖目录 |

### 3.2 可靠性

- 单实例；第二次启动唤起已有窗口。
- 数据库具备崩溃恢复、快速检查、每日备份；损坏时提供恢复向导。
- 崩溃时本地保存堆栈；下次启动提示；不自动上报。
- 迁移失败拒绝启动；更新失败回滚。
- 线程恢复失败明确提示，不静默丢失历史。
- 工具崩溃不影响主进程；终端进程组清理，避免僵尸进程。
- 文档写入备份失败时拒绝写入；恢复操作有确认。

### 3.3 安全与隐私

- 本地优先；除用户主动发送给模型的内容外，不向外部上传代码、文档、邮件、路径、日志。
- 不收集任何遥测数据；崩溃日志只保存在本地，由用户手动导出。
- 密钥只写入 `~/.craftwork/keys.json`，按提供商与 MCP 服务器保存，权限 0600；不进入配置、数据库、日志、工具输出与导出包。
- 文档、邮件、日历内容视为不可信数据；不执行宏、脚本与外部链接。
- 审批、审计、路径校验、沙箱、命令解析同时存在，沙箱不是唯一防线。
- 依赖锁定版本与校验和；发布签名；发布前跑漏洞扫描。
- 本地套接字 0600、数据目录 0700、密钥目录 0700；Windows 使用等效访问控制。

### 3.4 平台兼容

| 平台 | 最低版本 | 架构 | 说明 |
| --- | --- | --- | --- |
| macOS | 13 Ventura | arm64、amd64 | v1.0 首发平台 |
| Windows | 10 1903 及以上、11 | x64 | v1.0 首发平台；仅 x64 |
| Linux | Ubuntu 22.04、Fedora 38 | amd64、arm64 | Phase 2，不承诺时间 |

已知限制必须在发布说明与界面中标注：Windows 沙箱能力较弱；v1 不提供托盘与全局热键（原生菜单由 Wails3 提供）；Linux 不在 v1.0。

### 3.5 安装包与更新

- macOS 应用包 < 120 MB；Windows x64 安装包 < 80 MB。前端资源内嵌，编辑器、终端、设置按需加载。
- Windows 依赖系统 WebView2 Runtime；Windows 10 1803+ 通常已预装，缺失时由安装包引导安装。
- 不打包完整中日韩字体，优先使用系统字体。
- 发布产物包含校验和与软件物料清单。
- 更新清单签名，客户端内置公钥；下载后校验完整性与签名。
- macOS 与 Windows 使用辅助进程原子替换；失败回滚并保留上一版本。
- Linux 的安装包在 Phase 2 提供。

### 3.6 开源与许可证

- 许可证：Apache-2.0。
- 贡献流程：DCO（开发者原创声明）；不要求 CLA。
- 仓库包含源代码、构建说明、贡献指南、行为准则与安全披露流程。
- 发布产物包含第三方许可证清单与软件物料清单。
- 不使用许可证不兼容的依赖；新增依赖必须经过评审。

### 3.7 国际化与可访问性

- 支持简体中文与英文；文案不硬编码。
- 键盘优先；焦点可见；对比度可读；状态不只靠颜色。
- 无障碍基于 DOM 与 ARIA，v1 支持有限，在设置页与发布说明中明确说明。
- 界面字号、文档预览字号与终端字号可调。

| D-15 | 邮件与日历 | 通过 MCP 只读；内置推荐模板；应用内草稿；不自动发送、不自动创建、无服务端草稿 |
| D-16 | 浏览器 | 仅用系统浏览器打开链接；网页内容读取为 v1.1；浏览器自动化为后续版本 |
| D-17 | Work 界面 | 保留文件树、文件预览、文档面板；隐藏 Git、差异、终端与 Shell |
| D-18 | 技术栈 | Wails3 v3.0.0（桌面外壳与系统 WebView）+ Go 1.27.3 后端 + React 19 / TypeScript 5 前端 + assistant-ui 0.15 对话原语 + CodeMirror 6 编辑器 + xterm.js 终端；不使用 Electron、Tauri 或自带 Chromium 的方案 |

> **D-18 说明**：v3.0 文档曾把「不使用任何 WebView」列为硬约束。该约束已撤销。现在的边界是：应用自身界面运行在系统 WebView 中，但**不加载任意第三方网页、不执行不可信 HTML 与脚本、密钥不进入前端**。技术栈变更不改变产品定位与功能范围。

### 7.1 明确不做

- 邮件发送、日历创建与修改、服务端草稿。
- Windows arm64。
- 同一线程内切换 Code/Work 模式。
- 新建 Word/Excel 文档；v1 只修改已有文档。

这些能力不列入 P1 或 P2；如未来重新评估，需要单独立项并补充安全与隐私设计。
