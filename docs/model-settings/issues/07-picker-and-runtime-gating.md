# 7: 选择器与调用侧联动

**labels:** [ready-for-agent]
**Blocked by:** 3（供应商详情卡）、4（模型列表管理）

**What to build:** 启停语义全链路收口。聊天模型选择器只列「启用提供商 × 启用模型」，分组标题仅提供商名（去掉协议后缀）；历史会话引用不因禁用而清除，仍可解析显示名称；调用禁用提供商 / 模型时模型客户端工厂抛「该模型已停用，请重新选择模型」并映射到既有错误码（provider_unavailable 一族），界面 toast 可读；失败转移解析跳过禁用项，不回退到停用模型。单测覆盖选择器过滤、工厂抛错与转移跳过。详见 spec §9 联动语义。

## 验收标准

- [x] 禁用单个模型后选择器不再出现，恢复启用后重新出现
- [x] 禁用整个提供商后其全部模型从选择器消失
- [x] 历史会话中被禁模型的名称仍正常显示；发送时得到可读停用提示而非原始错误
- [x] 默认模型被禁时发送得到可读提示，不静默回退
- [x] 失败转移不落到禁用模型
- [x] 单测：工厂对禁用项抛错、转移解析跳过禁用项

## 进展

已实现（`4adbc81`）。`factory.client()` 对禁用提供商/模型抛 `provider_unavailable`「{提供商名}：该模型已停用，请重新选择模型」；`fallbackModel()` 跳过禁用候选（与密钥不可得同模式返回空）；`resolve()`/`findModel` 未动——历史会话引用仍可解析显示名称。`model-picker` 接入 `lib/provider-list.ts` 新纯函数 `selectableModels`（只列启用×启用、空组跳过），分组标题改为仅提供商名，空态覆盖「无提供商」与「全部被禁」。`tests/factory.test.ts` 7 例 + `tests/provider-list.test.ts` 扩 4 例，全量 154 绿。

配套修复（`43825d5`，协调人补）：runner.openSession 此前吞掉 ModelError 原始 message，界面只见「无法建立模型连接」；改为失败原因带出进入 failures，「已停用」语义透传到转移 notice 与最终错误文案——验收第 3/4 项由此完整达成。
