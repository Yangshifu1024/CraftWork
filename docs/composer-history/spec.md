# spec：composer 历史消息翻阅

输入区（composer）的会话历史回溯：按 ↑ 逐条回显当前会话发过的用户消息，可直接编辑复用或再次发送，按 ↓ 折返——类似终端 shell 的历史体验。范围**仅当前会话**（消息已常驻内存，纯前端实现，无后端改动）；翻阅只恢复**文本**，不恢复附件路径（原文件可能已失效）。

## 行为约定

1. **历史数据源**：当前会话 `chats[activeId].messages` 中 `role === "user"` 的消息，文本按 text part 提取（与消息复制按钮同模式）。翻阅条目为发送时的 trim 后文本。
2. **过滤规则**：空白消息跳过；「计划已确认，请按计划执行。」（批准计划的固定确认消息，非用户真实输入）排除；steer 引导消息与计划模式消息是用户真实输入，纳入。相邻重复去重（重试场景连发同样内容时，连续按 ↑ 不出现「没翻动」的假象）。
3. **触发条件（↑）**：非翻阅态下，仅当处于会话态（非草稿）且光标位于输入框第一行（`selectionStart` 之前无换行）才进入翻阅——多行输入时不抢光标的上移；已处翻阅态则无条件继续回溯。到最旧一条后停留。
4. **折返（↓）**：仅翻阅态拦截 ↓；逐条往回翻，越过最新一条时还原进入翻阅前暂存的原始输入并退出翻阅态。非翻阅态 ↓ 不拦截（光标正常下移）。
5. **回填与光标**：翻阅回填走输入框既有的 `setText` 双轨分流；回填后光标置于文本末尾，方便直接追加修改。
6. **退出翻阅态**：以下任一情况重置游标并丢弃暂存——用户手动键入（程序化回填不触发 onChange，互不干扰）；Enter 发送（含发送失败还原）；切换会话。退出后 ↑ 需重新满足首行光标条件才再次进入。
7. **草稿态**：无活动会话即无历史可翻，↑ / ↓ 一律不拦截，行为与现状一致。
8. **IME**：组词中方向键属候选操作，翻阅逻辑不介入（沿用既有 `isImeComposing` 守卫，置于其之后）。

## 实现落点

- 全部在 `src/renderer/src/components/conversation.tsx` 的 `Composer`：历史派生（useMemo）、游标 ref、`onKeyDown` 的 ↑ / ↓ 分支、自适应高度 effect 内的光标置尾、textarea `onChange` 与 `submit` 的游标重置。
- 不改 store、channels、Rust 侧；不引入持久化。
