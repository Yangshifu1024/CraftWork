# ADR-0003：R0–R4 风险分级与四档审批档位

- 状态：Accepted
- 日期：2026-10（自由档位后补，经风险确认守卫约束）

## 背景

Agent 的操作风险跨度极大：读文件无害，`rm -rf` 毁灭性。单一策略（全部询问或全部放行）要么逼疯用户，要么不安全。提示注入防护也无法识别所有恶意文本，需要结构性兜底。

## 决策

**风险五级**，按参数动态提升（越界路径 → R3；联网命令 → R3；`sudo`、`rm -rf`、`chmod 777` 等 → R4）：

| 等级 | 含义 | 默认策略 |
| --- | --- | --- |
| R0 | 只读 | 自动允许，记录审计 |
| R1 | 写工作区 | 每次询问；可本会话 / 本工作区授权 |
| R2 | 执行 | 每次询问；可按命令前缀授权 |
| R3 | 网络或越界 | 每次询问；不提供永久允许 |
| R4 | 破坏性 | 阻止 |

**档位四档**（档位是策略引擎输入，不改变风险分级本身）：

| 档位 | R0 | R1–R3 | R4 |
| --- | --- | --- | --- |
| 分级（默认） | 自动 | 询问 | 阻止 |
| 严格 | 自动 | 逐次询问，无永久允许 | 阻止 |
| 只读 | 自动 | 直接拒绝 | 直接拒绝 |
| 自由 | 放行 | 放行 | 放行 |

**自由档位**是唯一放行一切的档位，属于显式高危选择：

- 切换前必须弹出风险确认框逐条列出后果，确认后才写入设置（前端共享守卫）；策略层信任这次显式确认，不再二次拦截。
- 安全兜底从事前审批退化为「事后审计 + 写入前备份」；所有执行仍落审计。
- 受限工作区的断网保护一并被关闭，同样是用户显式选择。

**审批规则**：不自动超时；取消 / 关闭视为拒绝；弹窗默认焦点在「拒绝」；展示原始命令或路径而非模型解释；多个审批排队逐个处理。沙箱是纵深防御的一层，审批、路径校验、命令解析、审计必须同时存在。

## 后果

- 日常只读操作零打扰；危险操作必然有人类决定点。
- 「R3/R4 永不永久授权」与「受限工作区无永久授权」是硬约束，由服务端校验，不信任前端。
- 提示注入的对策是「高风险操作一定经过审批与审计」，而非试图识别恶意文本。
