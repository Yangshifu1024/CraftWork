# ADR-0005：API 密钥保存在 keys.json 而非系统凭据存储

- 状态：Accepted
- 日期：2026-10

## 背景

密钥需要一个跨平台（macOS / Windows / Linux Phase 2）、不依赖 GUI 交互、可随数据目录整体迁移的存放位置。操作系统提供的专用凭据存储（macOS Keychain、Windows 凭据管理器）更安全，但跨平台 API 碎片化、难以随导出/备份策略统一管理，且 server 模式与 CI 场景访问交互式凭据授权困难。

## 决策

- 密钥按提供商保存在 **`~/.craftwork/keys.json`**：目录 0700、文件 0600；Windows 使用仅当前用户可读写的等效访问控制。
- 文件结构：`providers` 节按提供商存 API 密钥；`mcp` 节按服务器标识存密钥、OAuth 令牌与刷新令牌。
- 启动时检查权限：宽于 0600 时自动收紧并记录警告；严重过宽时拒绝读取并提示修复，不静默降级。
- 原子写（临时文件 + rename）。
- 密钥不进入日志、数据库、事件、对话上下文、工具输出与导出包；前端只拿遮罩与来源。
- 优先级：`keys.json` > 环境变量；Shell 与 MCP 子进程的环境被清洗掉敏感变量。
- 备份与导出必须排除 keys.json。

## 明确接受的取舍

该方案以文件权限与磁盘加密为边界，**安全性低于操作系统专用凭据存储**：同一用户下的恶意进程仍可能读取。缓解手段是建议全盘加密并以最小权限运行。选择文件是为了跨平台一致性、可迁移性与无交互授权。

## 后果

- 密钥生命周期完全在 Go 进程内（`internal/secret`），前端永远接触不到明文。
- 数据目录可整体隔离（`CRAFTWORK_HOME`），利于测试与多实例。
- 换机迁移需用户重新输入密钥（导出包不含）。
