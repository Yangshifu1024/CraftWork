# ADR-0010：Office 文档做文本级读写，不做完整排版编辑

- 状态：Accepted
- 日期：2026-10

## 背景

Work 模式要求能修改 Word 与 Excel。完整实现 OOXML 排版引擎（图片、图表、页眉页脚、样式重排）工作量相当于一个 Office 套件，且写坏文档的后果由用户承担。

## 决策

- Word / Excel 只做**文本级读写**：解析 OOXML（标准库 zip + xml），修改段落、表格与单元格文本或公式，**保留原始 ZIP 部件、样式与结构**；不重建排版，不保证图片、图表、页眉页脚的完整保真。
- Word 替换要求完整位于同一个格式片段内；被拆分成多个 run 的文本提示改用更短片段。
- Excel 只读写值与公式，**不计算公式**。
- **PDF 只读文本层**；无文本层提示不支持 OCR，加密 PDF 拒绝读取；不支持编辑。
- v1 只修改已有 `.docx` / `.xlsx`；新建文档、旧版 `.doc` / `.xls`（提示转换）不在范围。
- 格式能力由 `doc.Format` 适配器接口（`Exts / Read / Replace`）承担，扩展名分派只在 `doc` 包注册一次。
- 写入属于 R1，**必须每次审批**；写前备份、可恢复；写入前展示文本级差异；文档内容视为不可信数据（不执行宏、脚本、外链）。

## 后果

- 50MB 文档可后台解析（目标 < 3 秒）不阻塞界面。
- 保存后 Word / Excel 可正常打开（结构未变，只改文本）。
- 「改排版」类需求明确不支持，避免半吊子保真；未来若支持需重新评估（需单独立项并补充安全与隐私设计）。
