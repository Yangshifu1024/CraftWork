# ADR-0009：WebView 安全边界——本地资源、严格 CSP、外链唯一出口

- 状态：Accepted
- 日期：2026-10（撤销早期「不使用任何 WebView」的约束，边界改为内容管控）

## 背景

早期设计曾把「不使用任何 WebView」列为硬约束，后因开发成本与生态原因撤销。但桌面 Agent 的界面进程一旦能加载任意网页，就等于把 Shell 与文件读写暴露给 web 内容。需要一条清晰的新边界。

## 决策

- **窗口只加载 `/`**（本地内嵌资源），禁止把绝对 URL 传给窗口；Wails3 没有默认 CSP 与导航拦截，安全靠 Go 中间件补齐。
- 生产构建资源响应带严格 CSP（`default-src 'self'`，禁内联脚本与远程资源）；server 模式同源。
- **外部链接只走 `AppService.OpenExternal`**（仅 http/https，前端先确认域名），系统浏览器打开；应用内不加载任何第三方网页。
- **Markdown 不渲染原始 HTML**；图片不加载远程地址；文档、邮件、工具输出等一律按不可信数据处理。
- 生产构建禁用 DevTools（production build tag）。

## 后果

- 界面进程被攻破也无法直接获得密钥（密钥只在 Go 进程）或执行任意导航。
- 渲染远程内容的能力为零：代价是聊天里不能内嵌网页预览（产品上也不需要）。
- 提示注入的边界与本 ADR 叠加：不可信内容影响不了 CSP、导航与密钥（配合 ADR-0003 的审批兜底）。
