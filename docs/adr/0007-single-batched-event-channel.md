# ADR-0007：单一批量事件通道 + 33ms 合并，大对象走命令

- 状态：Accepted
- 日期：2026-10

## 背景

模型流式输出逐 token 到达，直接逐条推送会打爆 WebView 的渲染与 IPC 带宽；而完全批量又会延迟工具状态、审批等高优先级信号。事件类型散落多个通道则难以保证顺序与去重。

## 决策

- **命令走绑定方法**（请求-响应，类型化）；**事件只走 `cw:events` 单一批量通道**，载荷带契约版本与线程内单调 `seq`。
- 文本与推理增量在 Go 侧按 **33ms 合并**（同一 `partId` 连续增量合并为一条）；单会话缓冲达到 32 条立即冲刷。
- **非增量事件（工具、审批、生命周期）立即推送**，保持顺序。
- 前端按 `seq` 去重；切换会话用快照替换，不重放事件。
- **大对象（文件内容、差异、终端历史）不进事件**，用命令按需拉取。
- 事件类型与载荷在 `internal/events` 与 `frontend/src/lib/types.ts` 两处保持一致。
- 终端输出单独合并（16KB 即推），与对话事件分离。

## 后果

- 流式渲染稳定（60fps 目标），输入延迟不受事件洪峰影响。
- 事件顺序与去重有单一依据（seq）。
- 修改事件结构时必须同步两端类型并重新生成绑定。
