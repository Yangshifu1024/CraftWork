## 2. 技术约束与选型

### 2.1 硬约束

1. 不使用 WebView、Electron、Tauri、Wails、WebView2、CEF、Qt WebEngine。
2. Go 作为主力语言；仅平台窗口与图形层允许 cgo。
3. 本地优先：会话、密钥、文件、日志默认保存在本机。
4. 可审计、可撤销：工具调用、审批、文件修改都有记录。
5. Apache-2.0 开源，DCO 贡献流程。

### 2.2 选型结论

| 领域 | 选型 | 理由与备选 |
| --- | --- | --- |
| 语言 | Go 1.23+ | 需求约束；并发模型适合流式与长任务 |
| 图形与输入层 | **Gio（gioui.org）** | 即时模式、全自绘、系统输入法与候选框支持较好、高 DPI 与拖放可用；适合精细还原设计方案 |
| 图形层备选 | Fyne v2.5 | 组件丰富、上手快；但控件体系难以做到设计稿的密度与细节，IME 支持一般 |
| 界面组件 | 自研组件库（基于图形层 canvas） | 三栏布局、消息流、编辑器、终端、差异均需自绘；避免受限于通用控件 |
| 数据库 | `modernc.org/sqlite` + `database/sql` | 纯 Go，避免扩大 cgo 范围；WAL 模式 |
| 终端 | `creack/pty` + 自研 VT 仿真 | Unix 无 cgo；Windows 使用 ConPTY |
| 文档解析 | 标准库 `archive/zip` + `encoding/xml` | OOXML 文本级读写，保留原始部件 |
| PDF 文本 | `ledongthuc/pdf`（或等价纯 Go 库） | 只读文本提取，检测无文本层的扫描件 |
| MCP | 官方 Go SDK；若接口不稳定则自研 JSON-RPC 客户端 | stdio 与 Streamable HTTP 两种传输 |
| 模型接入 | 自研 HTTP + SSE 客户端 | OpenAI、Anthropic、Gemini、OpenAI 兼容服务 |
| 密钥存储 | `~/.craftwork/keys.json` | 目录 0700、文件 0600；Windows 使用 ACL |
| 更新 | Ed25519 签名清单 + 辅助进程替换 | 失败回滚、保留旧版本 |

### 2.3 图形层选型的验证项（M0 必须完成）

| 验证项 | 通过标准 | 不通过时的处置 |
| --- | --- | --- |
| 中文输入法 | macOS 与 Windows 下候选框定位正确、组合文本可退格、撤销正常 | 改用系统原生输入控件或平台输入法桥接 |
| 长文本渲染 | 10 MB 文件滚动无明显掉帧 | 分页布局 + 可视区域渲染 |
| 终端性能 | 120×40 持续输出达到 60 fps | 脏行重绘、字形缓存 |
| 高 DPI | 200% 缩放下线条清晰、布局不破 | 使用逻辑像素与缩放因子 |
| 拖放与剪贴板 | 文件拖放、图片粘贴可用 | 调用平台 API 兜底 |

> 建议在 M0 用两周时间做一个“窗口 + 三栏 + 消息流 + 输入框”的纵向切片，验证图形层与输入法，再锁定选型。

## 3. 总体架构

### 3.1 分层

```text
┌──────────────────────────────────────────────────────────────┐
│ 表现层 internal/ui                                           │
│  窗口与布局 / 组件库 / 主题 / 输入法 / 拖放 / 通知            │
├──────────────────────────────────────────────────────────────┤
│ 应用层 internal/app                                          │
│  生命周期 / 单实例 / 命令与快捷键 / 路由 / 设置               │
├──────────────────────────────────────────────────────────────┤
│ 领域层                                                       │
│  agent（run 循环）  tools（工具）  policy（审批）  mcp        │
│  model（提供商）    doc（文档）    terminal（终端） editor    │
├──────────────────────────────────────────────────────────────┤
│ 基础设施层                                                   │
│  store（SQLite / 事件 / 审计 / 用量 / 备份）  secret（密钥）  │
│  platform（文件对话框 / 通知 / 剪贴板 / 单实例） update       │
└──────────────────────────────────────────────────────────────┘
```

依赖方向自上而下；领域层不依赖表现层。工具、模型、MCP 之间通过接口通信，便于用假实现做集成测试。

### 3.2 进程模型

```text
主进程
├─ UI 事件循环（主 goroutine）
├─ Agent 调度器（每线程一个 run goroutine）
├─ MCP 客户端（每服务器一个连接 goroutine）
├─ 用户终端（每标签一个 PTY 读协程）
└─ 后台任务（文档解析、备份、更新检查）

辅助进程
└─ 更新替换器（退出主进程后原子替换应用包）
```

- 单实例：本地套接字 `/tmp/craftwork-<uid>.sock`（0600）+ 文件锁；第二次启动唤起已有窗口。
- 工具执行、文档解析、终端读取都在独立 goroutine 中，崩溃隔离到单次 run 或单个标签。

### 3.3 关键数据流

```text
用户输入
  → Run 创建（thread_id, run_id）
  → 组装上下文（系统提示 + 历史 + 附件）
  → 模型流式输出（文本增量 / 推理增量 / 工具调用）
  → 工具调用
      → 策略检查（路径 / 命令 / 风险分级）
      → 需要审批 → 挂起 run，界面展示审批卡片
      → 批准 → 执行 → 结果回填
      → 拒绝 → 返回拒绝结果，模型继续或结束
  → 循环直到无工具调用或达到上限
  → 事件落库、用量记录、界面状态回到空闲
```

## 5. 核心模块设计

### 5.1 界面层（internal/ui）

#### 5.1.1 布局模型

对应《界面设计方案》第 2 节：

- 页面无独立顶栏，三栏顶部共用 48px：左栏标题行、聊天头部、面板标签栏。
- 左栏固定 268px；右栏默认 440px，可拖拽 320–760px；状态栏 27px。
- 窄窗口阈值 1180px：右栏自动折叠；打开时以浮层覆盖聊天区。
- 全屏面板覆盖中间区域，保留左栏与状态栏。

布局由 `shell.Layout` 计算，输出矩形区域给各视图；所有尺寸使用逻辑像素，按 DPI 缩放后绘制。

```go
type Layout struct {
    Sidebar   image.Rectangle
    Chat      image.Rectangle
    Panel     image.Rectangle
    Statusbar image.Rectangle
}

type PanelState int // Docked / Collapsed / Overlay / Maximized

func ComputeLayout(size image.Point, s PanelState, panelWidth, sidebarWidth int) Layout
```

#### 5.1.2 渲染与增量更新

- 即时模式：每帧根据状态生成绘制指令；状态保存在 `ViewModel`，不直接存在控件树中。
- 消息流只渲染可视区域（虚拟列表），单条消息超过 1 MB 时折叠。
- 文本布局结果按“消息版本号 + 宽度”缓存；流式更新只重排最后一条消息。
- 终端与差异视图按脏行重绘；编辑器按可视行区间绘制。
- 一帧内合并多次状态变更，使用 16ms 帧预算；超过预算的任务（文档解析、备份）放到后台。

#### 5.1.3 输入与输入法

- 通过图形层的文本输入事件接收组合文本；组合期间不提交到模型，只更新显示。
- 候选框位置由光标矩形计算，交给系统输入法；窗口移动、滚动时重新定位。
- 支持退格、删除、方向键、Home/End、撤销重做；输入法组合期间拦截快捷键。
- 聊天输入框、编辑器、终端分别维护焦点与输入上下文。

#### 5.1.4 主题

- 颜色 token 与《界面设计方案》8.1 一致，深色 / 浅色两套；代码主题独立。
- 主题切换时重建绘制资源；不重载窗口。
- 风险色只用于风险与状态，不做装饰。

#### 5.1.5 界面状态机

| 状态 | 触发 | UI 表现 |
| --- | --- | --- |
| 空闲 | run 完成 / 取消 | 输入框可用 |
| 运行中 | 发送消息 | 停止按钮、流式光标 |
| 等待审批 | 工具需要审批 | 审批卡片、状态徽章、取消按钮 |
| 错误 | 模型或工具失败 | 错误卡片、重试入口 |
| 面板折叠 | 窗口 < 1180 | 聊天区扩展、面板按钮高亮 |
| 面板全屏 | 点击全屏 | 覆盖中间区域、Esc 还原 |

### 5.2 Agent 内核（internal/agent）

#### 5.2.1 Run 生命周期

```go
type Run struct {
    ID       string
    ThreadID string
    Model    model.Client
    Tools    *tools.Registry
    Policy   *policy.Engine
    Store    *store.DB
}

func (r *Run) Execute(ctx context.Context, input Input) error
```

流程：

1. 写入 `run_started` 事件，线程状态设为运行中。
2. 组装上下文：系统提示、历史消息（分页加载）、附件、工作区信息。
3. 检查上下文占用；超过模型窗口 70% 时触发压缩（摘要替换早期消息），写入 `context_compressed` 事件。
4. 循环调用模型流式接口，增量写入事件表并推送到界面。
5. 收到工具调用：校验参数 → 策略检查 → 必要时审批 → 执行 → 结果回填。
6. 达到模型调用上限（默认 200）或工具调用上限（默认 100）时终止并报错。
7. 写入 `run_finished`，更新线程状态与用量。

#### 5.2.2 取消与超时

- `context.CancelFunc` 贯穿模型请求、工具执行、子进程。
- 取消时：中断 SSE 读取、向进程组发送 SIGTERM 后 SIGKILL、关闭 PTY、清理临时文件。
- 审批挂起时取消视为拒绝，写入审计。
- 模型请求默认超时 120 秒；工具默认 60 秒；`shell_exec` 默认 120 秒，可配置。

#### 5.2.3 子 Agent

- `task` 工具启动只读子 Agent，独立上下文，返回摘要。
- 子 Agent 不继承审批范围，不自主创建子 Agent；需要写入时提升权限并走审批。

#### 5.2.4 事件写入

- 对话事实来源是事件表；界面通过事件重建消息。
- 事件按线程分片写入，`seq` 单调递增；流式增量合并写入，避免每条增量一行。
- 崩溃恢复：启动时把未完成 run 标记为中断，界面提示可重试。

### 5.3 工具系统（internal/tools）

#### 5.3.1 接口

```go
type Tool interface {
    Name() string
    Description() string
    Risk(args map[string]any) policy.Risk
    Execute(ctx context.Context, args map[string]any) (Result, error)
}

type Registry struct {
    workspace string
    tools     map[string]Tool
    policy    *policy.Engine
    limiter   *Limiter // 读并行 8，写按工作区串行
}
```

#### 5.3.2 内置工具

| 工具 | 风险 | 实现要点 |
| --- | --- | --- |
| `fs_read` | R0 | 偏移与条数限制；二进制检测；大文件截断并提示 |
| `fs_list` | R0 | 名称、类型、大小、修改时间；忽略规则 |
| `fs_glob` | R0 | 通配符匹配，遵守忽略规则与深度限制 |
| `fs_grep` | R0 | 优先系统 `rg`，否则内置遍历；返回 `path:line:text` |
| `fs_write` | R1 | 写前备份；原子写（临时文件 + rename） |
| `fs_edit` | R1 | 精确替换；失败返回相似片段 |
| `apply_patch` | R1 | 解析 Git 风格补丁；支持预演 |
| `shell_exec` | R2/R3 | 工作目录限制、超时、输出截断、默认无网络 |
| `git_status` / `git_diff` / `git_log` | R0 | 只读命令封装 |
| `git_commit` | R1 | 默认不推送 |
| `todo_write` | R0 | 应用内状态，界面显示进度 |
| `task` | R2 | 子 Agent，默认只读 |
| `ask_user` | R0 | 阻塞当前 run，等待用户选择或输入 |
| MCP 工具 | 按服务器 | 命名 `mcp__服务器__工具` |

#### 5.3.3 输出处理

- 默认上限 32 KB；超出部分写入本地大输出文件并返回引用。
- 去除 ANSI 与控制字符；二进制只返回类型、大小、SHA-256。
- 错误返回结构化错误码（`path_outside_workspace`、`timeout`、`command_blocked` 等）与可读说明。

### 5.4 审批与策略（internal/policy + internal/sandbox）

#### 5.4.1 风险分级

| 等级 | 判定 | 默认策略 |
| --- | --- | --- |
| R0 | 只读 | 自动允许，记录审计 |
| R1 | 写工作区 | 每次询问（文档写入必须每次） |
| R2 | 执行 | 每次询问，或按命令前缀允许 |
| R3 | 网络或越界 | 每次询问，不提供永久允许 |
| R4 | 破坏性 | 阻止；双重确认也不放行 |

风险可按参数提升：访问工作区外路径或联网 → R3；`rm -rf`、`sudo`、`chmod 777` → R4。

#### 5.4.2 审批档位

对应《界面设计方案》9.2：

| 档位 | 行为 |
| --- | --- |
| 分级 | R0 自动；R1/R2/R3 询问；R4 阻止；R1/R2 提供会话与工作区授权 |
| 严格 | 写入与执行逐次询问；不提供永久允许 |
| 只读 | 只允许 R0；写入与执行直接拒绝并提示切档 |

审批档位是策略引擎的输入，影响 `AllowPermanent` 与默认决定，不改变风险分级本身。

#### 5.4.3 审批流程

```go
type Request struct {
    RunID  string
    Tool   string
    Risk   Risk
    Target string
    Detail string
    Facts  []Fact
    Diff   *DiffPreview
}

type Decision int // Deny / Once / Session / Workspace

type Approver interface {
    Ask(ctx context.Context, req Request) (Decision, Scope, error)
}
```

- 审批不自动超时；run 取消或线程关闭视为拒绝。
- 决定写入 `approvals` 与 `audit_log`，包含范围与操作者。
- 多个审批排队，界面一次展示一个；状态栏显示当前线程待审批数量。

#### 5.4.4 路径与命令安全

```go
func Resolve(workspace, rel string) (string, error) {
    abs := filepath.Clean(filepath.Join(workspace, rel))
    real, err := filepath.EvalSymlinks(abs)
    if err != nil { return "", err }
    if !strings.HasPrefix(real, workspace+string(os.PathSeparator)) {
        return "", ErrOutsideWorkspace
    }
    return real, nil
}
```

- 拒绝路径穿越、符号链接逃逸、UNC 绕过。
- 命令解析：分词 → 分类 → 命中断言列表；解析失败默认询问或拒绝。
- Shell 环境清洗：移除 `*_API_KEY`、`*_TOKEN`、`AWS_*`、`GITHUB_TOKEN` 等敏感变量。

#### 5.4.5 沙箱

| 平台 | 机制 | 能力 |
| --- | --- | --- |
| macOS | Seatbelt（`sandbox-exec` profile） | 限制写入工作区、默认断网 |
| Linux | bubblewrap / seccomp（Phase 2） | 限制挂载与网络 |
| Windows | 受限令牌 + AppContainer | 能力较弱，界面标注 |

沙箱不是唯一防线：审批、路径校验、命令解析、审计同时存在。

### 5.5 模型接入（internal/model）

#### 5.5.1 统一接口

```go
type Client interface {
    Stream(ctx context.Context, req Request) (<-chan Chunk, error)
    Capabilities() Capabilities
}

type Capabilities struct {
    Stream, Tools, Vision, Reasoning, Structured bool
}

type Chunk struct {
    Text      string
    Reasoning string
    ToolCalls []ToolCall
    Usage     *Usage
    Done      bool
}
```

#### 5.5.2 提供商适配

| 提供商 | 协议 | 说明 |
| --- | --- | --- |
| OpenAI | Chat Completions / Responses + SSE | 工具调用使用 function calling |
| Anthropic | Messages + SSE | 工具使用 tool_use / tool_result |
| Gemini | generateContent + SSE | 工具使用 functionDeclarations |
| OpenAI 兼容 | Chat Completions | DeepSeek、Kimi、GLM、Qwen、Ollama、vLLM 等，各自作为独立提供商 |

- 能力矩阵决定界面控件与请求参数：不支持图片输入时不发送图片，不支持推理内容时不展示折叠块。
- 失败转移仅限 429、5xx、超时、连接失败；工具调用中间失败不转移。
- 错误分类：限流、认证、超时、上下文溢出、服务不可用、参数错误。

#### 5.5.3 密钥

- 路径固定 `~/.craftwork/keys.json`，结构：

```json
{
  "version": 1,
  "providers": { "anthropic": "sk-ant-...", "deepseek": "sk-..." },
  "mcp": {
    "gmail": { "access_token": "...", "refresh_token": "...", "expires_at": 0 },
    "postgres-prod": { "secret": "..." }
  }
}
```

MCP 节点按服务器保存：简单密钥使用字符串或 `secret` 字段，OAuth 服务器使用包含 `access_token`、`refresh_token`、`expires_at` 的对象。文件只由应用读写，不纳入版本控制、不导出、不写入日志、不进入对话上下文。

- 启动时检查目录 0700、文件 0600；权限过宽拒绝读取并提示修复。
- 优先级：密钥文件 > 环境变量；界面标注来源，支持迁移。
- 密钥不进入日志、数据库、对话上下文、工具输出与导出包；日志脱敏匹配 `sk-`、`ghp_`、`AKIA` 等模式。

### 5.6 MCP 客户端（internal/mcp）

- 传输：stdio 与 Streamable HTTP；远程只允许 HTTPS。
- 生命周期：启动 → 初始化 → 发现工具 → 注册 → 健康检查 → 重连（指数退避）→ 关闭。
- 工具命名 `mcp__服务器__工具`，调用前校验 JSON Schema。
- 首次连接展示来源、命令或地址、将获得的权限；确认后加入信任列表。
- 每个服务器独立环境变量；密钥与 OAuth 令牌从 keys.json 的 `mcp` 节点读取。
- 工具描述视为不可信内容；模型不能自动安装、启动或修改服务器。
- 每个服务器可配置允许列表、拒绝列表、风险等级与可见模式（Code / Work / 两者）。

### 5.7 本地存储（internal/store）

#### 5.7.1 数据库

- SQLite（WAL），`busy_timeout=5000`，最大连接 4。
- 表结构见第 7 节。
- 迁移：版本表 + 事务迁移；失败回滚并拒绝启动，提示备份路径。
- 每日首次启动备份（`VACUUM INTO`），保留 7 份；启动时快速完整性检查（`PRAGMA quick_check`）。

#### 5.7.2 事件与索引

- 线程事件是对话事实来源；应用表只存界面索引、审计、配置、用量。
- 大文本与二进制写入 `~/.craftwork/blobs/<hash>`，按内容去重；数据库只存引用。
- 软删除 7 天后清理事件与本地大文件。

#### 5.7.3 导出

- 导出数据库、配置、最近日志；不包含 keys.json。
- 导入时重新输入密钥。

### 5.8 文档处理（internal/doc）

#### 5.8.1 Word（.docx）

- 解析：`word/document.xml`、`styles.xml`、`numbering.xml`、关系文件；建立段落与表格的文本索引。
- 写入：按文本节点替换，保留 `w:rPr`、表格结构、页眉页脚、图片与关系；不重建排版。
- 差异：段落级与表格单元格级；写入前生成文本级差异供审批。

#### 5.8.2 Excel（.xlsx）

- 解析：`xl/workbook.xml`、`xl/worksheets/*.xml`、`sharedStrings.xml`、`styles.xml`；读取值与公式。
- 写入：修改单元格值与公式（`<f>`），保留样式、合并单元格、列宽；不计算公式。
- 保存后由 Excel 重算；界面展示公式与缓存值。

#### 5.8.3 PDF

- 只读：提取文本层；无文本层时提示“不支持 OCR”。
- 不执行宏、脚本、外部链接；文档内容视为不可信数据。

#### 5.8.4 备份与恢复

- 写入前复制到 `~/.craftwork/backups/<原名>.<时间戳>`，SHA-256 校验。
- 备份失败拒绝写入；恢复需确认，恢复后内容与备份一致。
- 文档写入每次审批；审计记录路径、变更摘要与备份位置。

### 5.9 终端（internal/terminal）

- PTY：`creack/pty`（Unix）；Windows 使用 ConPTY。
- 仿真器：自研或基于 `vt10x`；支持 16 色 / 256 色 / 真彩色、粗体斜体下划线反色、光标闪烁。
- 宽字符：东亚宽字符按 2 列处理；字体缺失回退系统等宽字体。
- 滚动缓冲 10,000 行；搜索与匹配高亮。
- 尺寸同步：窗口或面板变化时同时更新仿真器与 PTY。
- 退出状态可见；关闭标签释放进程组，避免僵尸进程。
- 用户终端不经过 Agent 审批；Agent 的 `shell_exec` 走策略引擎，两条路径独立。

### 5.10 编辑器与差异（internal/editor）

- 文本缓冲：分段存储（按行或按块），支持 10 MB 文件 < 1 秒打开。
- 语法高亮：按语言的关键字、字符串、注释、数字、类型；增量高亮可视区域。
- 搜索替换：正则与字面量；结果高亮、逐个或全部替换。
- 差异：Myers 算法生成统一差异；并排视图按行配对；大差异只渲染可视区域。
- 应用补丁：预演 → 备份 → 原子写；拒绝时文件不变。

### 5.11 平台集成（internal/platform）

| 能力 | 实现 |
| --- | --- |
| 文件对话框 | macOS NSOpenPanel / NSSavePanel；Windows IFileDialog |
| 系统通知 | macOS UNUserNotificationCenter；Windows Toast |
| 剪贴板 | 文本与图片；粘贴图片到输入框 |
| 拖放 | 文件拖放附件；目录提示添加工作区 |
| 单实例 | 本地套接字 + 文件锁；第二次启动唤起窗口 |
| 窗口状态 | 尺寸、位置、最大化、分栏宽度、主题、最后工作区与模式 |
| 外部链接 | 系统浏览器打开；打开前确认域名 |

### 5.12 更新（internal/update）

1. 检查更新清单（stable / beta），验证 Ed25519 签名。
2. 下载到临时目录，校验 SHA-256 与签名。
3. 安装前备份数据库。
4. 退出主进程，由辅助进程原子替换应用包；失败回滚并保留旧版本。
5. 启动后执行迁移；迁移失败回滚并提示。

## 6. 关键流程

### 6.1 一次对话 run

```text
UI 发送
  → app 创建 run（线程锁保证单 run）
  → agent 组装上下文
  → model.Stream
      → 文本增量 → 事件写入 → UI 增量渲染
      → 工具调用 → policy.Check
          → 无需审批 → tools.Execute → 结果回填
          → 需要审批 → approvals 插入（等待）
              → UI 审批卡片
              → 用户允许 → 执行 → 回填
              → 用户拒绝 → 写入拒绝结果
  → 无工具调用 → run_finished
  → 用量记录、审计、线程状态空闲
```

### 6.2 审批挂起与恢复

```text
tool_call
  → policy 判定 R1
  → approver.Ask(ctx, request)    // 阻塞
  → UI 展示卡片（默认焦点拒绝）
  → 用户决定
      → Decision 写入 approvals + audit
      → ctx 继续或返回 ErrDenied
  → run 继续循环
```

- 取消 run：`ctx` 取消，`Ask` 返回 `ErrCanceled`，审批记为拒绝。
- 进程崩溃：启动时把等待中的审批标记为中断，线程状态置为错误并提示重试。

### 6.3 文档写入

```text
doc_write 请求
  → 解析原文件，定位段落/单元格
  → 生成文本级差异
  → 审批（每次）
  → 备份原文件（失败则终止）
  → 写入 OOXML（临时文件 + 原子替换）
  → 校验可打开、结构未破坏
  → 更新界面与审计
```

### 6.4 面板折叠与全屏（UI 状态）

```text
窗口宽度 < 1180
  → PanelState = Collapsed
  → 点击聊天头部面板按钮
      → PanelState = Overlay（绝对定位覆盖聊天区右侧）
  → 点击全屏
      → PanelState = Maximized（覆盖中间区域）
  → Esc
      → 还原为 Collapsed 或 Docked
```

### 6.5 上下文压缩

```text
估算 token
  → 超过模型窗口 70%
  → 摘要早期消息（保留系统提示、最近 N 轮、工具结果摘要）
  → 写入 context_compressed 事件
  → UI 显示“上下文已压缩”，可查看摘要
```

## 7. 数据模型

```sql
CREATE TABLE threads (
  id TEXT PRIMARY KEY,
  mode TEXT NOT NULL,              -- code / work
  title TEXT NOT NULL,
  model_id TEXT NOT NULL,
  status TEXT NOT NULL,            -- idle / running / awaiting / error
  archived INTEGER NOT NULL DEFAULT 0,
  deleted_at INTEGER,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE TABLE events (
  id TEXT PRIMARY KEY,
  thread_id TEXT NOT NULL,
  run_id TEXT,
  seq INTEGER NOT NULL,
  kind TEXT NOT NULL,              -- user_message / text / reasoning / tool_call / tool_result / approval / error / notice
  payload BLOB NOT NULL,           -- JSON
  created_at INTEGER NOT NULL,
  UNIQUE(thread_id, seq)
);

CREATE TABLE runs (
  id TEXT PRIMARY KEY,
  thread_id TEXT NOT NULL,
  status TEXT NOT NULL,            -- running / done / canceled / error / interrupted
  started_at INTEGER NOT NULL,
  finished_at INTEGER,
  error_code TEXT,
  error_message TEXT
);

CREATE TABLE tool_calls (
  id TEXT PRIMARY KEY,
  run_id TEXT NOT NULL,
  name TEXT NOT NULL,
  args BLOB NOT NULL,
  risk TEXT NOT NULL,
  status TEXT NOT NULL,
  output_ref TEXT,
  duration_ms INTEGER
);

CREATE TABLE approvals (
  id TEXT PRIMARY KEY,
  run_id TEXT NOT NULL,
  tool_call_id TEXT NOT NULL,
  risk TEXT NOT NULL,
  decision TEXT NOT NULL,          -- allow / deny / canceled
  scope TEXT NOT NULL,             -- once / session / workspace
  decided_at INTEGER NOT NULL
);

CREATE TABLE audit_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  ts INTEGER NOT NULL,
  thread_id TEXT,
  tool TEXT NOT NULL,
  risk TEXT NOT NULL,
  decision TEXT NOT NULL,
  scope TEXT,
  detail TEXT
);

CREATE TABLE usage (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  ts INTEGER NOT NULL,
  thread_id TEXT,
  model_id TEXT NOT NULL,
  input_tokens INTEGER,
  output_tokens INTEGER,
  cache_tokens INTEGER,
  reasoning_tokens INTEGER,
  cost_micros INTEGER
);

CREATE TABLE mcp_servers (
  id TEXT PRIMARY KEY,
  transport TEXT NOT NULL,         -- stdio / http
  endpoint TEXT NOT NULL,
  enabled INTEGER NOT NULL,
  trusted INTEGER NOT NULL,
  scope TEXT NOT NULL,             -- code / work / both
  risk TEXT
);

CREATE TABLE settings (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

CREATE TABLE backups (
  id TEXT PRIMARY KEY,
  path TEXT NOT NULL,
  backup_path TEXT NOT NULL,
  hash TEXT NOT NULL,
  created_at INTEGER NOT NULL
);

CREATE TABLE blobs (
  hash TEXT PRIMARY KEY,
  path TEXT NOT NULL,
  size INTEGER NOT NULL
);

CREATE TABLE schema_migrations (
  version INTEGER PRIMARY KEY,
  applied_at INTEGER NOT NULL
);
```

索引：`events(thread_id, seq)`、`audit_log(ts)`、`audit_log(thread_id)`、`usage(ts, model_id)`、`threads(mode, updated_at)`。

func RegisterBuiltin(r *tools.Registry, ws string) {

依赖关系：M0 → M1 → M2 顺序不可颠倒；M3 可在 M2 后半段并行；M4 依赖 M2/M3 的安全面完成。

## 15. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 图形层输入法支持不足 | 中文输入不可用 | M0 优先验证；必要时平台输入法桥接或换图形层 |
| 自绘组件工作量大 | 进度延迟 | 先做纵向切片；组件按需实现；复用绘制原语 |
| 编辑器性能 | 大文件卡顿 | 分块缓冲、可视区域绘制、增量高亮 |
| OOXML 写入破坏结构 | 文档损坏 | 保留原始部件、原子写、保存后校验、写入前备份 |
| PDF 文本提取质量 | 摘要不准确 | 明确只读与 OCR 限制；提示扫描件 |
| Windows 沙箱能力弱 | 安全边界弱 | 界面标注能力差异；审批与路径校验兜底 |
| 更新替换失败 | 应用不可用 | 辅助进程、失败回滚、保留旧版本 |
| MCP 生态差异 | 工具不可用 | 兼容层、超时与重连、错误可读 |
