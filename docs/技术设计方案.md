## 2. 技术约束与选型

### 2.1 硬约束

1. **Go 承担内核与全部系统能力**：Agent、工具、策略、存储、PTY、文件系统、密钥。
2. **界面层使用 Wails3 + React + TypeScript**，运行在系统 WebView 中。
3. **不加载任意第三方网页**：界面资源只来自本地内嵌包；外链只交给系统浏览器。
4. **不执行不可信 HTML 与脚本**：Markdown 原始 HTML 按文本处理；资源响应带 CSP。
5. **本地优先**：会话、密钥、文件、日志默认保存在本机。
6. **可审计、可撤销**：工具调用、审批、文件修改都有记录。
7. **不使用 Electron、Tauri 或自带 Chromium 的运行时装包**。
8. Apache-2.0 开源，DCO 贡献流程。

### 2.2 选型结论

| 领域 | 选型 | 理由与备选 |
| --- | --- | --- |
| 桌面外壳 | **Wails3 v3.0.0**（精确锁定） | Go 主控、系统 WebView、不打包 Chromium、单二进制；备选 Tauri 被否（Rust 主控、前端能力边界不同） |
| 后端语言 | Go 1.27.3 | 并发模型适合流式与长任务；与工具、PTY、SQLite 生态匹配 |
| 前端框架 | React 19 + TypeScript 5 + Vite 8 | Wails3 官方模板；assistant-ui 同时支持 React 18/19 |
| 对话界面 | `@assistant-ui/react@0.15.32`（headless primitives） | 提供消息流、输入区、附件与流式状态；不强制 Tailwind，可用原型 CSS 自绘 |
| 状态管理 | Zustand 5 | 按域拆 store，配合 Wails 事件流做细粒度订阅 |
| 图标 | `lucide-react@1.66.0` | 24×24 描边风格与原型一致；tree-shakeable；只通过 `<Icon>` 包装组件使用 |
| 编辑器 | CodeMirror 6 | 行号、语法高亮、搜索、IME、大文件虚拟化成熟 |
| 终端 | xterm.js 6 + `creack/pty` | 真实 PTY 流；前端只负责渲染与输入 |
| Markdown | `@assistant-ui/react-markdown` + `remark-gfm` + `highlight.js` | 代码块高亮映射到原型 token；原始 HTML 不渲染 |
| 样式 | 原型 CSS 分区迁移（不使用 Tailwind） | 保留 class 名与 DOM 结构，视觉 1:1 复用，风险最低 |
| 数据库 | `modernc.org/sqlite` + `database/sql` | 纯 Go，避免扩大 cgo 范围；WAL |
| 文档解析 | 标准库 `archive/zip` + `encoding/xml`（M3） | OOXML 文本级读写，保留原始部件 |
| PDF 文本 | 纯 Go PDF 文本提取库（M3） | 只读文本层；扫描件提示不支持 OCR |
| MCP | 官方 Go SDK 或自研 JSON-RPC 客户端（M4） | stdio 与 Streamable HTTP |
| 模型接入 | 自研 HTTP + SSE 客户端 | OpenAI Chat Completions、Anthropic Messages 与 OpenAI 兼容服务；不接入 Gemini 原生协议 |
| 密钥存储 | `~/.craftwork/keys.json` | 目录 0700、文件 0600；启动时自动收紧权限 |
| 更新 | Ed25519 签名清单 + 辅助进程替换（M4） | 失败回滚、保留旧版本 |

### 2.3 备选与取舍

- **Electron**：自带 Chromium，包体与内存不可接受，且 Go 只能作为 sidecar。
- **Tauri**：Rust 主控与前端能力边界同 Go 内核不匹配，工具链引入 Rust。
- **Fyne / Gio**：自绘组件工作量大，无法直接复用原型 CSS；中文输入与复杂排版风险高。
- **Tailwind + shadcn**：与原型 13px 密度、手写 token 体系冲突，会带来大量覆盖样式。

## 3. 总体架构

### 3.1 分层

```text
┌──────────────────────────────────────────────────────────────┐
│ 前端（React + TypeScript）                                    │
│  三栏布局 / 聊天 / 面板 / 浮层 / 主题 / 键盘                   │
│  无系统访问权限，所有能力经绑定与事件访问                       │
├──────────────────────────────────────────────────────────────┤
│ IPC（Wails3 绑定 + 事件通道）                                  │
│  命令：类型化方法调用，请求-响应                                │
│  事件：cw:events 批量推送，33ms 合并                            │
├──────────────────────────────────────────────────────────────┤
│ Wails3 宿主层（Go）                                           │
│  窗口 / 单实例 / WebView / 资源服务器 / CSP / 生命周期          │
├──────────────────────────────────────────────────────────────┤
│ 应用服务层（Go）                                              │
│  service（绑定层）→ agent / tools / policy / model / mcp       │
│  workspace / doc / terminal / editor / store / secret          │
├──────────────────────────────────────────────────────────────┤
│ 基础设施                                                      │
│  SQLite（WAL）/ 文件系统 / PTY / keys.json / 备份目录           │
└──────────────────────────────────────────────────────────────┘
```

依赖方向自上而下。前端不直接访问数据库或文件系统；所有路径校验、命令分级、密钥读取都在 Go 侧完成。

### 3.2 进程模型

```text
主进程
├─ Wails3 事件循环（主 goroutine）
├─ Wails3 服务调用（每个请求独立 goroutine，可取消）
├─ Agent 运行器（每个会话最多一个 run goroutine）
├─ 事件总线冲刷协程（33ms 节拍）
├─ 终端读取协程（每个 PTY 一个）
└─ 后台任务（文档解析、备份、更新检查，M3/M4）

WebView 渲染进程
└─ React 应用（消息流、编辑器、终端、浮层）
```

- 单实例：Wails3 `SingleInstance.UniqueID = "com.craftwork.app"`；第二实例启动时唤起主窗口。
- 工具执行、模型请求、终端读取都在独立 goroutine 中，崩溃隔离到单次 run 或单个终端标签。
- WebView 崩溃不会带崩 Go 进程；M1 增加前端错误边界与窗口重建。

### 3.3 关键数据流

```text
用户输入
  → 前端 ChatService.Send（绑定调用）
  → Go 写入 user_message 事件，创建 run
  → Agent 组装上下文（系统提示 + 历史 + 工作区）
  → 模型流式输出
      → 文本/推理增量 → 事件批处理 → 前端增量渲染
      → 工具调用 → 策略检查
          → 无需审批 → 执行 → 结果回填 → 事件
          → 需要审批 → approval.requested（挂起）
              → 前端审批卡片 → ChatService.DecideApproval
              → 允许 → 执行 → 结果回填
              → 拒绝 → 返回拒绝结果，模型继续或结束
  → run 完成 → run.completed → 前端状态回空闲
  → 事件落库、审计、用量
```

### 3.1 上下文占用与输出速度口径

- **上下文占用** = 最近一次主对话模型请求返回的 `input + output` token，每轮调用后**覆盖**更新（不累加）；持久化在 usage 表，由 `ThreadView.ContextTokens` 带出，run 进行中通过 `usage.updated` 事件的 `contextTokens` 字段实时刷新。
- **输出速度**：run 进行中由前端按流式字符估算（字符 ÷4 ÷ 经过秒数）；一轮完成后显示真实值 `output ÷ 模型调用耗时`。耗时随每轮用量落库（usage 表 `duration_ms` 列），因此重启或重新拉取会话列表后仍能展示最近一轮的真实速度。
- **sidecar 隔离**：自动命名标题等非主对话调用的用量照常计入累计与费用，但 `usage.updated` 载荷不带 `contextTokens` 等字段，避免 sidecar 小请求压低上下文水位。
- **会话累计 tokens**（`threads.tokens`）保持原有累加语义，与占用口径分离：占用回答「现在上下文里有多少」，累计回答「这个会话一共花了多少」。
- 会话没有调用记录时，前端回退到「累计 + 字符估算」的兜底显示。

## 5. Wails3 宿主集成

### 5.1 应用与窗口

- `application.New` 注册九个服务：App / Settings / Thread / Chat / Workspace / Provider / Audit / Terminal / Document。
- 窗口：`1440×900`，最小 `960×640`，名称 `main`；macOS 使用 `MacTitleBarHiddenInset` + 48px 隐形标题栏，前端为左上角红绿灯预留 82px。
- `BackgroundColour` 使用深色背景，避免首帧白闪。
- `EnableFileDrop` 打开，文件拖放路径交给前端附件条；附件内容由 Go 侧读取后进入模型上下文。
- 原生菜单由 Wails3 提供；托盘与全局热键不在 v1。

### 5.2 单实例

```go
SingleInstance: &application.SingleInstanceOptions{
    UniqueID: "com.craftwork.app",
    OnSecondInstanceLaunch: func(application.SecondInstanceData) {
        // Restore / Show / Focus 主窗口
    },
}
```

Wails3 只负责通知，不自动唤起窗口；回调必须显式 `Restore/Show/Focus`。

### 5.3 资源与 CSP

- `//go:embed all:frontend/dist` 把前端构建产物嵌入二进制。
- `AssetFileServerFS` 提供本地资源，附加中间件写入安全头：
  - 生产：`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`
  - 开发：额外允许 Vite 的内联脚本与本地 WebSocket。
- 窗口 URL 固定为 `/`，**禁止传入绝对 URL**。Wails3 桌面端没有统一的导航拦截钩子，因此外部链接必须走 `AppService.OpenExternal`（只允许 http/https）。
- 生产构建禁用 DevTools：macOS / Windows 由 `production` build tag 控制。

### 5.4 生命周期

- 启动：打开数据库 → 清理上次未完成的 run → 读取密钥 → 创建事件总线 → 装配服务 → 恢复活动工作区与审批档位 → 创建窗口。
- 关闭：`OnShutdown` 关闭事件总线；服务与数据库按逆序释放。
- 崩溃恢复：启动时把 `running` 的 run 标记为 `interrupted` 并记录错误码，挂起审批标记为 `canceled`；对应会话标记为 `error`，同时写入一条可重试的 `error` 事件，界面显示错误卡片并保留已产生的消息。快照携带 `lastSeq`，重新打开会话后从数据库恢复完整状态。

### 5.5 平台目标

只提供桌面目标：macOS、Windows、Linux。已移除模板中的 iOS 与 Android 目标。

## 6. IPC 契约

### 6.1 命令方向（前端 → Go）

- 每个服务方法生成一个 TypeScript 函数；参数与返回值由 Wails3 生成类型。
- 需要取消的长调用由 Go 方法接收 `context.Context`（Wails3 会省略该参数），前端用 `CancellablePromise.cancel()` 触发。
- 当前版本错误以可读文本返回（Promise reject）；M1 增加稳定的 `code` 字段（`path_outside_workspace`、`timeout`、`command_blocked`、`unauthorized` 等）。
- 前端不传原始文件内容以外的系统对象；路径一律是相对工作区的字符串，由 Go 侧解析与校验。

### 6.2 事件方向（Go → 前端）

单一批量事件 `cw:events`，载荷：

```ts
interface Batch {
  v: number;          // 契约版本，当前为 1
  threadId: string;
  events: Array<{
    seq: number;      // 会话内单调递增
    type: string;
    threadId?: string;
    runId?: string;
    ts: number;       // 毫秒
    data: any;
  }>;
}
```

事件类型：

| 类型 | 载荷要点 |
| --- | --- |
| `run.started` | `messageId`、`modelId` |
| `text.delta` / `text.completed` | `partId`、`text` |
| `reasoning.delta` / `reasoning.completed` | `partId`、`text` |
| `tool.started` / `tool.completed` | `partId`、`toolCallId`、`name`、`args`、`risk`、`status`、`output`、`durationMs` |
| `approval.requested` | `partId`、`approvalId`、`toolCallId`、`tool`、`risk`、`target`、`facts`、`args`、`allowPermanent` |
| `approval.resolved` | `partId`、`approvalId`、`status`、`decision`、`scope` |
| `todo.updated` | `partId`、`items` |
| `error` | `partId`、`code`、`message`、`retryable` |
| `run.completed` / `run.canceled` / `run.failed` | `status`、可选 `code` / `message` |
| `thread.updated` | `threadId`、`status`、可选 `thread` |
| `usage.updated` | `inputTokens`、`outputTokens` |
| `settings.updated` / `workspace.updated` | 变更摘要 |
| `terminal.output` / `terminal.exit` | `sessionId`、`data` / `exitCode` |

### 6.3 合并与背压

- 文本与推理增量在 Go 侧按 **33ms 合并**；同一 `partId` 的连续增量合并为一条。
- 单会话缓冲达到 32 条事件立即冲刷；非增量事件（工具、审批、生命周期）立即推送，保证顺序。
- 终端输出使用 `TerminalDelta`，同一会话合并，合并长度达到 16KB 立即推送。
- 前端按 `seq` 去重；切换会话时用快照替换本地消息，不依赖事件重放。
- 大对象（文件内容、差异、终端历史）通过独立命令按需拉取，不塞进事件。

### 6.4 取消语义

- `ChatService.Cancel` → `Runner.Cancel` → `context.CancelFunc`；同时取消会话内等待中的审批。
- 模型请求随 SSE 连接中断；`shell_exec` 取消时杀掉整个进程组（Unix `Setpgid` + `SIGKILL`）。
- 前端刷新或窗口关闭时，`context` 被取消，审批按 `canceled` 落库。

### 6.5 审批跨 IPC

原型里的进程内阻塞 `Approver.Ask` 已作废。当前实现：

```text
Agent → Approvals.Request(ctx, request)
  → 写审批卡部件 + approvals 表（decision = NULL）
  → approval.requested 事件 → 前端审批卡片
  → ChatService.DecideApproval(approvalId, allow, scope)
  → Approvals.Resolve → 校验状态机 + 写 approvals / audit_log
  → approval.resolved 事件 → Request 返回 Outcome
```

审批模块内部维护唯一状态机（`waiting → approved / denied / canceled`）、
等待表、授权缓存与卡片载荷；服务层只做 IPC 参数校验。

- 授权范围：`once` / `session` / `workspace`；`workspace` 写入 `settings.policy.workspace_grants`。
- Shell 命令按前缀复用授权：取前两个片段（第二段是选项时只取第一段），例如允许 `git status` 后 `git status --short` 不再询问；包含管道、重定向、命令串联或 `sudo` / `bash -c` 等包装的命令只允许精确匹配这一次调用。
- R3 / R4 永不提供永久授权；只读档位直接拒绝。
- 取消、窗口关闭、应用退出统一按拒绝或取消落审计。

## 8. Agent 内核

### 8.1 Run 生命周期

1. `ChatService.Send` 写入 `user_message` 事件，创建 `runs` 记录（`message_id` 指向助手消息）。
2. 会话状态置 `running`，推送 `thread.updated`。
3. `Runner.execute` 从事件表重建历史，进入循环：
   - 调用模型流式接口；
   - 文本/推理增量推事件；
   - 工具调用：策略评估 → 审批 → 执行 → 结果回填；
   - 无工具调用则结束。
4. 完成更新 `runs.status = done`、会话 `idle`、记录用量，并广播 `run.completed`。
5. 取消更新 `runs.status = canceled` 并广播 `run.canceled`；失败写 `error` 部件与 `run.failed`。

生命周期状态以 `runs` 表为准，不再额外写入 `run_started` / `run_finished` 事件。
事件写入与广播统一经过 `internal/record.Recorder`：一次调用完成 seq 分配、
落库与推送，部件 kind 到事件类型的映射只存在一处。

- 单次 run 的模型调用往返上限可配置（`maxIterations` 设置项，默认 300，0 表示不限制），由 Runner 通过设置服务实时读取。
- 单次模型请求超时 180 秒。
- 工具输出默认 32KB 截断。

### 8.2 上下文与历史

- 系统提示词由 `internal/agent/prompt` 分节组装：前缀块（产品身份，无缓存标记）、稳定块（安全边界与行为契约，带缓存标记）、动态块（模式规则、环境公告、Git 快照、指令文件，带缓存标记）。环境事实（日期、平台、Shell、Git、两级 AGENTS.md）每次运行开始时由 `envcontext.go` 收集，读取失败降级省略；稳定块内容与运行时事实隔离，保证跨会话缓存命中。分节清单与变更约定见 `docs/系统提示词契约.md`。
- 历史从事件表物化：用户消息、助手文本、工具调用与工具结果按顺序重建。
- 一个 run 的文本与工具调用合并为一条 assistant 消息；工具结果作为独立 `tool` 消息回填给模型。
- 推理内容不发送回模型。
- 上下文压缩：历史超过模型窗口 70% 时摘要早期消息，保留最近轮次与工具调用链；写入 `context_compressed` 事件，并在提示条中提供摘要查看入口。摘要失败时保留原始历史继续本轮运行。摘要同时以 `context_summary` 事件持久化（携带覆盖截止序号，不进界面、不广播），后续运行重建历史时直接复用，同一批早期消息不再重复摘要。
- 附件：来自系统文件选择框与输入区粘贴。文件选择的路径经 `policy.Resolve` 校验工作区边界；粘贴内容由 `AppService.SavePastedAttachment` 以 base64 写入数据目录 `attachments/`，读取时同样经过边界与符号链接检查。文本限 1MB、图片限 5MB、单条消息最多 10 个、总计 12MB；`.env`、密钥与不支持的二进制文件不读取，只用说明文本代替；附件内容带边界标记，并作为不可信数据处理。

### 8.3 事件持久化

- 会话事实来源是 `events` 表；流式增量只推送不逐条落库，文本完成时写入完整部件。
- 部件事件 ID 即前端 `partId`；`approval_resolved` 通过同一 `partId` 合并到审批卡片。
- 快照按 `thread_id` 读取事件并按 `message_id` 分组，附上 `runs` 状态与待审批。

- 取消时杀掉整个进程组，避免残留子进程。

## 10. 审批与策略

### 10.1 风险分级

| 等级 | 判定 | 默认策略 |
| --- | --- | --- |
| R0 | 只读 | 自动允许，记录审计 |
| R1 | 写工作区 | 每次询问；可本会话 / 本工作区授权 |
| R2 | 执行 | 每次询问；可按命令前缀授权 |
| R3 | 网络或越界 | 每次询问；不提供永久允许 |
| R4 | 破坏性 | 阻止 |

参数可提升风险：越界路径 → R3；`curl` / `git push` / `npm install` 等 → R3；`sudo`、`rm -rf`、`chmod 777`、`git reset --hard` 等 → R4。

### 10.2 审批档位

| 档位 | R0 | R1–R3 | R4 |
| --- | --- | --- | --- |
| 分级 | 自动 | 询问 | 阻止 |
| 严格 | 自动 | 逐次询问，无永久允许 | 阻止 |
| 只读 | 自动 | 直接拒绝 | 直接拒绝 |
| 自由 | 自动放行 | 自动放行 | 自动放行 |

档位是策略引擎输入，不改变风险分级本身。

「自由」档位是唯一放行一切的档位，实现约束：

- 前端切换到自由档位前必须弹出风险确认框（共享守卫 `lib/approval.ts`），用户确认后才保存设置，取消保持原档位；策略层信任这次显式确认，不再做二次拦截。
- `policy.Engine.Action` 对自由档位一律返回 `allow`，优先于只读、严格与受限工作区判断；`AllowsPermanent` 仍返回 false（审批卡不会出现，永久授权无意义）。
- 安全兜底从「事前审批」退化为「事后审计 + 写入前备份」：所有执行仍走 `record.Recorder` 落库与审计。

工作区信任状态叠加在档位之上：

- **信任工作区**：按档位执行。
- **受限工作区**：R3（网络 / 越界）直接拒绝；R1 / R2 仍逐次审批；**不提供任何永久授权**，已有的会话 / 工作区授权在受限模式下不生效。

### 10.3 路径与命令安全

```go
func Resolve(workspace, rel string) (string, error) {
    // 1. 工作区 EvalSymlinks
    // 2. 相对路径以工作区为根拼接
    // 3. 词法校验：越界立即返回 ErrOutsideWorkspace
    // 4. EvalSymlinks 后再次校验，阻止符号链接逃逸
    // 5. 新文件解析父目录
}
```

- 拒绝路径穿越、符号链接逃逸、UNC 路径。
- 命令分类：危险命令 R4；联网命令 R3；普通命令 R2。
- 前端传入的路径不属于可信输入。

### 10.4 审计

- 每次工具调用写 `audit_log`：时间、会话、run、工具、风险、决定、范围、详情。
- 审批决定同时写 `approvals` 与 `audit_log`。
- 前端「审计」面板读取最近 200 条，可按决定过滤。

## 11. 模型接入

### 11.1 统一接口

```go
type Client interface {
    Stream(ctx context.Context, req Request) (<-chan Chunk, error)
}

type Chunk struct {
    Text, Reasoning string
    ToolCall        *ToolCall
    Usage           *Usage
    Done            bool
    Err             error // 仅 Go 内部
}
```

### 11.2 提供商

应用只支持三种协议，且**没有任何内置提供商**：首次启动的提供商列表为空，所有提供商都由用户从模型目录添加或手动配置。

| 协议 | 实现 | 说明 |
| --- | --- | --- |
| `openai` | Chat Completions + SSE | OpenAI 官方接口 |
| `anthropic` | Messages + SSE | `tool_use` / `tool_result` |
| `openai-compatible` | Chat Completions + SSE | Ollama、公司网关、OpenRouter、Groq 等兼容服务 |

- 提供商与模型元数据来自 models.dev 的构建期快照，不保存在代码常量里；用户导入时把选中的提供商与模型写成普通配置，保存在 `settings.model.custom_providers`。
- 密钥仍按提供商保存在 `keys.json`；导入目录的提供商同时保留 models.dev 给出的环境变量名，读取时优先使用。
- 模型能力矩阵决定前端控件：不支持图片时不发送图片，不支持推理时不展示推理块。
- 统一错误码：`auth`、`rate_limit`、`timeout`、`context_overflow`、`provider_unavailable`、`invalid_request`、`canceled`；前端错误卡片按错误码给出处理建议。
- 429、5xx、超时与连接失败在建立流之前最多重试 3 次（指数退避）；仍然失败时按设置的失败转移模型切换一次。
- 失败转移仅限 429、5xx、超时、连接失败；工具调用过程中不转移，流建立后的错误直接失败并保留已产生内容。
- 密钥优先级：`keys.json` > 目录给出的环境变量 > 按提供商 ID 推导的环境变量；前端只看到来源与遮罩。

### 11.3 模型引用

同一模型 ID 可能出现在多个提供商下（例如两个 OpenAI 兼容网关都提供 `gpt-5.5`），因此会话、默认模型与失败转移模型保存 `providerID/modelID` 形式的引用。

- `ModelInfo.ID` 仍然是调用提供商接口时使用的原始模型 ID。
- `model.Ref` / `FindModelByRef` 按引用精确解析；`model.Resolve` 兼容旧数据里只有原始 ID 的情况。
- 解析失败时返回空，不回退到任何“默认模型”；发送消息前服务层会给出“尚未选择模型”的可读错误。
- `buildProvider` 只限制同一提供商内部的模型 ID 重复，允许不同提供商出现同名模型。

### 11.4 模型目录

- `cmd/modelsync` 在开发或发版前从 `https://models.dev/api.json` 拉取目录，应用 `catalog.rules.json` 里的协议映射、端点覆盖与排除规则，裁剪后生成 `internal/model/catalogdata/catalog.json.gz` 与 manifest。
- 运行时通过 `//go:embed` 读取 gzip，建立只读索引；不访问网络。
- 目录只作为“可添加的候选列表”，不会自动创建提供商。用户选中后再写入用户配置。
- 排除 Google / Gemini 原生协议、Azure、Bedrock、Vertex 与模板化端点；OpenRouter 等兼容网关里的 Gemini 模型仍可导入，因为它们走 OpenAI 兼容协议。
- 价格用于用量估算，单位美元 / 百万 token；`recordUsage` 把费用写入 `usage.cost_micros`，界面标注“估算，非账单”。

### 11.5 会话标题

- 新建会话的 `title_auto = 1`，标题为「新对话」；用户手动改名或复制会话时置为 0。
- 第一轮模型请求建立后，如果会话仍允许自动命名：首条消息清洗后不超过 20 个字符时直接使用原文作为标题，不发起模型请求；超过上限时与正文流式响应并行调用**本次运行实际使用的模型**生成标题，请求设置 8 秒超时、最多 128 个输出 token，不等待助手回复。
- 标题清洗后限制在 20 个字符内；模型超时、报错或返回空文本时，回退到首条用户消息提取（纯附件消息使用文件名）。
- 写回标题使用带 `title_auto = 1 AND title = '新对话'` 条件的更新，保证并发消息或手动改名不会被覆盖；更新后广播 `thread.updated`。
- 标题调用的 token 用量与费用照常计入用量统计。

### 11.6 密钥

```json
{
  "version": 1,
  "providers": { "deepseek": "sk-..." },
  "mcp": { "gmail": { "access_token": "...", "refresh_token": "...", "expires_at": 0 } }
}
```

- 目录 0700、文件 0600；权限过宽时自动收紧并记录警告。
- 原子写：临时文件 + `rename`。
- 密钥不进入日志、数据库、对话上下文、工具输出与导出包。

## 12. MCP（M4）

- 传输：已实现 stdio（一行一个 JSON-RPC 消息）；Streamable HTTP 尚未接入。
- 生命周期：启动 → `initialize` → `tools/list` → 注册动态工具 → 关闭；健康检查与指数退避重连尚未接入。
- 工具命名 `mcp__服务器__工具`；`tools/call` 结果按不可信数据处理，调用走 R2 审批。
- 服务器配置保存在 `settings.mcp.servers`，设置页支持添加、连接、断开与移除；启动时自动连接已启用的服务器。
- 子进程只继承必要的环境变量，模型密钥与常见令牌（`*_API_KEY`、`*_TOKEN`、`AWS_*` 等）会被过滤。
- 远程传输、服务器信任列表与工具级授权细化尚未实现。

## 13. 本地存储

### 13.1 数据库

SQLite（WAL），`busy_timeout=5000`，最大连接 4。迁移使用 `PRAGMA user_version`，在事务内逐版执行：v1 建表，v2 为会话增加 `title_auto`，用于首轮自动命名且不覆盖手动改名。

```sql
CREATE TABLE threads (
  id TEXT PRIMARY KEY, mode TEXT NOT NULL, title TEXT NOT NULL,
  title_auto INTEGER NOT NULL DEFAULT 0,
  model_id TEXT NOT NULL DEFAULT '', workspace_id TEXT NOT NULL DEFAULT '',
  status TEXT NOT NULL DEFAULT 'idle', archived INTEGER NOT NULL DEFAULT 0,
  tokens INTEGER NOT NULL DEFAULT 0, deleted_at INTEGER,
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
);

CREATE TABLE workspaces (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, path TEXT NOT NULL UNIQUE,
  trust TEXT NOT NULL DEFAULT 'restricted',
  created_at INTEGER NOT NULL, last_opened_at INTEGER NOT NULL
);

CREATE TABLE events (
  id TEXT PRIMARY KEY, thread_id TEXT NOT NULL, message_id TEXT NOT NULL,
  run_id TEXT, seq INTEGER NOT NULL, kind TEXT NOT NULL,
  payload TEXT NOT NULL, created_at INTEGER NOT NULL,
  UNIQUE(thread_id, seq)
);

CREATE TABLE runs (
  id TEXT PRIMARY KEY, thread_id TEXT NOT NULL, message_id TEXT NOT NULL,
  status TEXT NOT NULL, model_id TEXT NOT NULL DEFAULT '',
  started_at INTEGER NOT NULL, finished_at INTEGER,
  error_code TEXT, error_message TEXT
);

CREATE TABLE approvals (
  id TEXT PRIMARY KEY, thread_id TEXT NOT NULL, run_id TEXT NOT NULL,
  tool_call_id TEXT NOT NULL, tool TEXT NOT NULL, risk TEXT NOT NULL,
  decision TEXT, scope TEXT, requested_at INTEGER NOT NULL, decided_at INTEGER
);

CREATE TABLE audit_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT, ts INTEGER NOT NULL,
  thread_id TEXT, run_id TEXT, tool TEXT NOT NULL, risk TEXT NOT NULL,
  decision TEXT NOT NULL, scope TEXT, detail TEXT
);

CREATE TABLE usage (
  id INTEGER PRIMARY KEY AUTOINCREMENT, ts INTEGER NOT NULL, thread_id TEXT,
  model_id TEXT NOT NULL, input_tokens INTEGER NOT NULL DEFAULT 0,
  output_tokens INTEGER NOT NULL DEFAULT 0, cache_tokens INTEGER NOT NULL DEFAULT 0,
  reasoning_tokens INTEGER NOT NULL DEFAULT 0, cost_micros INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL);

CREATE TABLE backups (
  id TEXT PRIMARY KEY, path TEXT NOT NULL, backup_path TEXT NOT NULL,
  hash TEXT NOT NULL, size INTEGER NOT NULL DEFAULT 0, created_at INTEGER NOT NULL
);
```

索引：`threads(mode, archived, updated_at)`、`events(thread_id, seq)`、`runs(thread_id, started_at)`、`approvals(thread_id, decision)`、`audit_log(ts)`、`usage(ts)`、`usage(model_id, ts)`、`backups(created_at)`。

### 13.2 事件与快照

- 事件按会话 `seq` 单调递增，写入在事务内分配序号。
- 快照读取事件、按 `message_id` 分组，附上 `runs` 状态与待审批。
- `approval_resolved` 事件合并到同 `partId` 的审批部件。
- 大文本与二进制外置 blobs 在 M1 实现。

### 13.3 备份与恢复

- 写入前备份到 `~/.craftwork/backups/<文件名>.<时间戳>`，记录 SHA-256 与大小。
- 恢复前确认；恢复写回原路径并追加审计。
- 每日数据库备份（`VACUUM INTO`）在 M1 实现。

## 14. 文档、终端与编辑器

### 14.1 文档（M3）

- Word：解析 `word/document.xml`，按段落与表格输出文本；文本替换要求完整位于同一个格式片段内，保留其余 ZIP 部件、样式与结构；被拆分成多个 run 的文本会提示改用更短片段。
- Excel：解析工作簿、关系文件、共享字符串与工作表 XML；只读取值与公式，不计算公式；写入使用 inlineStr 或数值节点，保留单元格样式。
- PDF：只读文本层（FlateDecode / 字面量与十六进制字符串）；无文本层提示不支持 OCR，加密 PDF 拒绝读取。
- 格式差异由 `doc.Format` 适配器承担（`Exts / Read / Replace`），扩展名分派只在 `doc` 包内注册一次；新增格式只需实现接口并注册一行。
- 写入前由工具层备份原文件并走审批；`DocumentService.Preview` 通过 `doc.Supported` 判断是否走文档解析，不再重复扩展名 switch。
- 限制：不执行宏、脚本或外部链接；旧版 `.doc` / `.xls` 提示转换；PDF 不支持编辑与 OCR。

### 14.2 终端

- Go 侧 `creack/pty` 启动用户 shell，`TerminalService` 管理创建、写入、调整尺寸与关闭。
- 输出通过 `TerminalDelta` 批量推送，前端 xterm.js 渲染；滚动缓冲 10,000 行。
- 终端输出搜索使用 `@xterm/addon-search`，支持高亮、上一个 / 下一个匹配与 Esc 关闭。
- 用户终端不经过 Agent 审批；Agent 的 `shell_exec` 走策略引擎，两条路径独立。
- 尺寸同步：ResizeObserver → `FitAddon` → `TerminalService.Resize`。

### 14.3 编辑器与差异

- CodeMirror 6：行号、语法高亮、搜索、只读/编辑切换、IME。
- 语言按扩展名懒加载；Go 直接使用 `@codemirror/lang-go`。
- 差异在 Go 侧计算（LCS + 3 行上下文，超过 20,000 行或 4,000,000 格子退化为整段替换），前端渲染统一/并排两种视图。
- 保存前备份；外部修改时以 `expectedHash` 阻止覆盖，并提示重新加载；二进制与超过 2MB 的截断文件禁止编辑。
